# 文本纯化与消除机器生成腔调指南（Humanizer）

## 概述

指导识别并彻底消除大语言模型（LLM）在生成文本时普遍存在的特征性套话、空洞比喻、虚假热情、互联网黑话与机器翻译腔，使文字回归真实、严谨、质朴的人类书面语态。本技能吸收了维基百科“识别 AI 写作迹象”治理准则以及大量真实的语言纠偏经验。

**根本成因**：
```
大语言模型基于概率统计预测下一个词元，输出往往倾向于统计学上最常见的平庸表达，导致大批高频陈词滥调反复出现
```

## 适用场景

- “帮我润色这段文章，去掉浓重的 AI 味和官话套话，让它听起来像真人写的”
- “审查即将发布的更新日志、技术文档或对外说明，消除里面的机器腔调”
- “根据我平时的写作风格样本，重写这段技术总结”
- 在智能体自身输出对外汇报材料时，执行前置自检，杜绝浮夸修辞

## 一、 AI 常见写作顽疾与消除对照表

在审查与重构文本时，重点排查并根除以下典型机器特征：

| 顽疾类型 | 大模型高频典型套话 | 为什么不通 | 规范的人类真实表达 |
| :--- | :--- | :--- | :--- |
| **虚假的宏大叙事** | “在当今快节奏的世界中”、“作为……的关键切入点” | 空洞无物，读者第一眼就产生阅读疲劳。 | **直接陈述事实**：“当系统面临高并发写入时……” |
| **生硬的机械直译** | 脱离语境的生硬翻译与怪异连词 | 脱离中文真实使用习惯，生造概念。 | **说人话**：“执行下一行代码”、“将日志内容正式写入主文件” |
| **过度礼貌与空洞吹捧** | 无依据的浮夸评价与过度礼貌套话 | 假大空评价，缺乏数据支撑。 | **给出确凿数字**：“该改动使内存占用降低了 45%。” |
| **互联网大厂黑话** | 模糊具体物理动作的空泛黑话词汇 | 模糊真实物理动作，故弄玄虚。 | **还原为具体动作**：“沟通核实”、“形成规范”、“提供支持” |
| **机械的对称总结** | “总而言之，它不仅改变了 A，更是重塑了 B” | 刻板公式化结尾，废话连篇。 | **直接给出下一步动作或省去无意义的总结段落**。 |

## 二、 文本纯化标准五步流水线

当接收到一段带有浓重 AI 腔调的文本时，按如下流程处理：

### 第一步：通读并标记 AI 典型特征
逐句扫描文章，标记出其中的空洞形容词、成对出现的浮夸修辞、无意义的并列排比以及生硬机翻词汇。

### 第二步：提取核心事实框架
将所有华丽的修辞外衣剥除，提炼出这段文字真正想要表达的**主谓宾核心事实与技术结论**。

### 第三步：使用质朴工程书面语重写
以严肃、克制、准确的文字重新组织句子：
- 一个句子说清楚一件事；
- 结论先行：先给明确结论，再说具体影响，最后陈述细节；
- 凡是涉及状态与改动的，一律使用确切的数字或客观状态陈述。

### 第四步：注入真实的人格与温度
根据目标受众调整语态：面向技术同仁时保持严谨硬核，面向普通用户时通俗直白；消除毫无感情的机械播报感。

### 第五步：终极反向审视
通读重写后的段落，反问自己：“这段话里还有没有让人一眼看出来是机器人编造的痕迹？”如果依然存在哪怕一句假大空套话，坚决二次重写直至完全自然。

## 三、 自检自身输出（项目已有行话参照表时）

当项目已经确立了一套固定的行话替换表（例如写在系统规范或语言包中的词到词对照），助手自己的回复同样受其约束。以下三条是硬要求：

1. **交付前逐条比对，不凭记忆**。写完回复后，把参照表的每个词条在草稿里检索一遍，命中数必须为零。凭“我读过规范”就以为不会违反，实际仍会反复用到表内词——规范是陈述性知识，不自动约束生成。
2. **解释“我清洗了哪些词”时最容易违规**。汇报清洗成果的段落会大量引用待清洗词本身，极易把违规词重新写回回复。做法：引用违规词时一律放进行内代码或引号并注明“原表述”，正文叙述只用规范词。
3. **不得污染已完成的成果**。修正一处表述时，只改那一处，不要顺手重写相邻已验收的段落。
4. **拦截插件只能拦无歧义的词**。把多义词写进拦截表，会误杀正规技术表述，且拦截表与规范正本需要双处同步，维护成本高。根本办法是在源文件里把翻译做准，不靠下游硬替换。

### 欧化被动语态与机翻句式

英文被动句直译成中文会留下明显的翻译腔，且往往把真正的信息主体推到最后。识别与改写：

| 机翻句式 | 问题 | 改写 |
| :--- | :--- | :--- |
| 你由名为 X 的模型驱动 | 被动语态，主体模糊 | 你实际使用的模型是 X |
| 该功能被设计为用于处理…… | 双重被动叠加 | 该功能用于处理…… |
| 数据被写入到文件中 | “被”“到”冗余 | 数据写入文件 |
| 这是一个被广泛使用的工具 | 无主被动句 | 该工具使用广泛 |

判别方法：句中出现“被”字时，问一句“谁做的”。如果施动者不重要或不存在，直接改成主动句或名词句。

### 直译生造词：不在任何词表里的机翻痕迹

有一类机翻痕迹不会出现在行话表里，因此逐条检索也查不出来：把英文词逐个换成汉字，字面通顺，但中文技术文档里没人这么说。判别方法：把词放回句子，问一句“中文技术文档会这样写吗”。

典型形态有三种：

1. **生造职位与机构名**。`a summarization agent` 译成某个带“专员”的职位名，读者会以为存在这个岗位。按实际职责写：“你负责为当前对话生成一份上下文摘要”。
2. **英文名词直接换字**。英文的抽象名词（如表示回退机制、资源上限、待填内容的词）直接换成汉字，往往能得到一个能看懂但不地道的说法。这类词必须按当次语境重选，不能建表一次性替换。
3. **比喻化改写**。把工程结构说成建筑部件、把流程说成物理动作，看似生动，实际降低了精确度。

处理原则：每次出现都单独判断。同一个英文词在不同语境下恰当译法不同，建一张表机械替换必然误杀正规术语。

### 被问什么就答什么，不要绕着答

用户提出一个具体问题（“仓库新版是本地汉化还是原版”“到底改哪个文件”），回答的第一句必须直接给出答案，再展开依据。

常见跑偏形态：

| 跑偏写法 | 问题 | 直接写法 |
| :--- | :--- | :--- |
| 先讲三层背景，最后才说结论 | 读者要翻到最后才知道答案 | 第一句就是答案 |
| 把同一组事实换个角度再说一遍 | 读者以为在回避问题 | 一次说清，不重复 |
| 给了一堆方案却不给推荐 | 决策成本推回给读者 | 先给推荐，再列备选与代价 |

判别方法：写完回答后，把第一段遮住，只看第二段以后。如果读者无法从中找到被问的那个问题的答案，就是跑偏了。

用户连续追问同一个问题（“你还是没说清楚”），说明前一次回答没有直接命中，而不是用户没听懂。此时不要重复解释，直接给一句话结论。

## 四、 检查核对清单

- [ ] 是否彻底删除了“在当今快节奏的时代”等空洞套话与陈词滥调？
- [ ] 常见的空泛大厂套话是否已全部还原为具体的物理动词？
- [ ] 句子结构是否主谓宾完整，杜绝了生造词与机械直译？
- [ ] 表达是否结论先行，第一遍读就能毫无障碍地理解？
- [ ] 若项目已有行话参照表，是否逐条检索过自己的回复且命中数为零？
- [ ] 是否清除了“被设计为”“被用于”一类欧化被动句式？
- [ ] 是否检查了不在词表里的直译生造词（生造职位名、英文名词直接换字、比喻化改写）？
- [ ] 原文用全大写强调的约束，中文里是否用“只是”“绝不”“必须”承接了同等强度？
