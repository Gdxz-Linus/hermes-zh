# 宝玉信息图与高密度数据可视化指南（Infographics）

## 概述

规范基于信息结构（Layout）与视觉风格（Style）双重维度，将非结构化长文本、技术架构与业务数据转化为高密度、高信息量且完全可编辑的信息图表。输出统一采用原生 HTML/SVG 矢量格式，兼顾严谨的工程逻辑与现代美学排版。

## 适用场景

- “把这段系统重构方案做成一张高密度技术信息图”
- “为汇报材料制作一张对比清晰的双方案优劣评估图”
- “生成包含里程碑、技术栈与阶段目标的工程推进路线图”

---

## 一、 核心二维结构设计

信息图的呈现由 **“信息结构版式（21 种）”** 与 **“视觉美学风格（21 种）”** 自由组合而成：

### 1. 21 种信息结构版式（Layout Gallery）

| 版式标识 | 中文结构名称 | 最优适用场景与逻辑形态 |
| :--- | :--- | :--- |
| `linear-progression` | **线性推进图** | 时间轴、开发演进时序、标准操作流程（SOP） |
| `binary-comparison` | **二元对比图** | 方案 A 与方案 B 对照、改造前与改造后对比、优势与劣势 |
| `comparison-matrix` | **多维对比矩阵** | 多个选型方案在性能、成本、复杂度等多维度的综合打分评估 |
| `hierarchical-layers` | **层级金字塔** | 优先级划分、系统架构分层（硬件/内核/运行环境/业务应用） |
| `tree-branching` | **树状分类图** | 知识体系分类树、代码模块结构、目录资产层级分解 |
| `hub-spoke` | **核心辐射图** | 以核心系统为中心，向外辐射多个支撑组件与协作服务 |
| `structural-breakdown` | **结构剖析图** | 组件拆解分解图、技术模块横截面细节 |
| `bento-grid` | **便当盒九宫格（默认）** | 综合仪表盘式全景展现，容纳多个并列或不同尺寸的要点信息块 |
| `iceberg` | **冰山模型图** | 区分显性表象（水上部分）与底层隐性复杂度（水下基石） |
| `bridge` | **跨越桥梁图** | 核心问题与诉求 $\to$ 实施路径 $\to$ 最终达成效果的桥接过渡 |
| `funnel` | **漏斗转化图** | 流程筛选、请求过滤链路、逐步淘汰与转化指标 |
| `isometric-map` | **等距技术地图** | 具备立体感的系统物理拓扑、空间模块分布与网络拓扑 |
| `dashboard` | **数据指标看板** | 核心量化指标、监控指标看板、图表汇总 |
| `periodic-table` | **元素周期表格** | 工具箱全景、技术栈家族清单、多类别资产平铺速查 |
| `comic-strip` | **叙事连环分镜** | 用户故事演进、异常故障发生到排除的故事化推演 |
| `story-mountain` | **故事山起伏图** | 业务挑战积累、技术攻坚瓶颈、突破解决与平稳上线运行 |
| `jigsaw` | **拼图互锁图** | 多个相互依赖、彼此契合才能正常运转的模块协同关系 |
| `venn-diagram` | **韦恩交叠图** | 概念交集、技能复合领域、多重标准同时满足的重合区域 |
| `winding-roadmap` | **蜿蜒路线图** | 跨年度长期战略演化、重大里程碑发展足迹 |
| `circular-flow` | **循环图** | 敏捷迭代周期、PDCA 循环、数据采集-处理-回流流水线 |
| `dense-modules` | **高密度信息块** | 适合高阶技术指南、密集参数与规则并列的极高密度排版 |

### 2. 视觉美学风格（Style Gallery 常用选型）

- `craft-handmade`：手绘纸质质感（默认推荐，亲和力强，图解生动）；
- `corporate-memphis`：现代扁平矢量风（商务汇报与技术立项推荐，色彩对比鲜明）；
- `technical-schematic`：工程蓝图风格（深蓝背景配精密线条，适合深度技术架构）；
- `pop-laboratory`：坐标网格与实验精度风（适合科研文献图解与实验室指标分析）；
- `morandi-journal`：莫兰迪低饱和配色（沉稳低调，适合高管汇报与全局架构概览）。

## 二、 业务内容与版式组合推荐原则

| 业务输入类型 | 推荐版式组合 | 视觉设计重点 |
| :--- | :--- | :--- |
| **技术选型对比（如网关架构对比）** | `binary-comparison` + `corporate-memphis` | 突出关键差异指标，左侧放原架构，右侧放新架构 |
| **工程开发规范（如质量保证流程）** | `linear-progression` + `technical-schematic` | 串联起前置检查、沙箱编写、真实验证与收尾审查阶段 |
| **项目综合全景概览** | `bento-grid` + `craft-handmade` | 主区块承载核心结论，辅助区块容纳技术参数与状态 |
| **底层复杂机制剖析** | `iceberg` 或 `structural-breakdown` | 区分显式外部调用与底层多线程、内存模型细节 |

## 三、 输出规范与代码质量要求

1. **统一采用现代流式 HTML/SVG 格式**：
   - 生成的图表必须自包含在单个 HTML 文件中，通过内联 SVG 实现矢量图标与几何连线；
   - 杜绝纯位图截图平铺，必须保证文本、代码块与指标数值在任意缩放倍率下清晰可读，且支持选中复制。
2. **色彩与视觉层次规约**：
   - 限制主题色种类：采用 1 种主色调（占 60%）、1 种辅助色（占 30%）与 1 种警示/高亮色（占 10%）；
   - 背景必须提供舒适的对比度，文本采用高对比度深色或在暗黑模式下使用清晰明亮的前景色。
3. **交付载体**：
   - 将生成的 HTML 文件直接写入指定的输出目录（如 `D:\Hermes\生成的图表\`）；
   - 在回复中通过应用内预览指令 `::preview{file="绝对路径.html"}` 呈现，便于直接浏览与导出。
