# 独立 HTML 原型与前端设计流程指南（Claude Design）

## 概述

指导在终端和本地文件系统环境中，从零构思、设计、实现并验证高质量的单文件 HTML 前端原型（如产品展示页、演示文稿（幻灯片）、数据看板、微型交互组件实验室）。本技能重点管辖**设计方法与审美标准**，指导如何深入剖析设计需求、构建合理的排版骨架、消除大模型常见的千篇一律排版套话，并输出自包含且能在任何现代浏览器中直接打开的独立 HTML 产物。

## 适用场景

- “帮我设计一个微型工具的前端单页原型，包含即时输入与图表展示功能”
- “制作一个用于技术立项汇报的高清纯 HTML HTML 演示幻灯片”
- “开发一个独立的交互式前端组件实验室，支持切换不同状态并实时预览”
- “优化一段粗糙的前端页面代码，提升其视觉质感与交互细节”

## 一、 核心设计方法论：六阶段设计全流程

从零构建独立前端产物时，严格按如下六阶段推进：

```
第一阶段：需求拆解（确定受众群体、核心功能目标、情绪基调与视觉定位）
  ↓
第二阶段：排版与信息架构设计（确立文字排版阶梯、栅格系统与视觉重心）
  ↓
第三阶段：单文件代码编写（输出包含样式与逻辑的自包含 HTML，杜绝外部重型框架）
  ↓
第四阶段：交互与动效润色（添加自然的 CSS 渐变、悬浮微动效与焦点状态）
  ↓
第五阶段：真实验证与自检（检查极端视口宽度下的响应式适配，排查溢出与换行缺陷）
  ↓
第六阶段：交付与呈现（写入本地文件，并在会话中提供直接预览）
```

---

## 二、 拒绝 AI 常见排版套话（核心质量铁律）

大模型直接生成的前端代码通常存在高度雷同、缺乏灵魂的特征，在设计中必须严格规避以下通病：

1. **杜绝千篇一律的紫色发光渐变**：不要无脑使用从紫色到蓝色的渐变背景或发光文字；根据业务主题选择有深度的色彩体系（如工程感深蓝、工业灰、极简黑白或温暖大地色）；
2. **文字层级必须具备鲜明反差**：大标题（H1）、次级标题（H2）与正文之间要有清晰的字号差距（如 48px vs 24px vs 15px），杜绝所有文字大小挤在一起的平淡排版；
3. **保持舒适留白，拒绝空间压迫**：区块之间应保持充足的外边距与内边距（通常采用 16px、24px、48px、64px 的倍数阶梯），让页面呼吸感更强；
4. **组件交互细节完整**：按钮不仅要有静态样式，必须完整定义鼠标悬停（Hover）、点击激活（Active）以及键盘聚焦（Focus-visible）的视觉反馈。

## 三、 单文件独立 HTML 编写标准

1. **完全自包含原则**：
   - 所有 CSS 样式内嵌在 `<style>` 标签中，所有交互 JavaScript 代码内嵌在 `<script>` 标签中；
   - 杜绝依赖本地本地 `npm install` 或复杂的 Webpack/Vite 打包链路，确保该 HTML 文件双击即可离线运行；
2. **轻量现代矢量图标**：
   - 界面中的图标优先使用内联 `<svg>` 代码，不引入体积庞大的第三方字体图标库；
3. **支持键盘无障碍访问**：
   - 交互按钮与表单元素必须使用标准的原生 HTML 标签（如 `<button>`、`<input>`），杜绝在普通 `<div>` 上直接绑定点击事件导致失去无障碍支持。

---

## 四、 交付与呈现规范

1. **写盘落位**：使用 `write_file` 工具将代码写入用户指定目录或工作区的页面设计目录（如 `D:/Hermes/页面设计/prototype.html`）；
2. **会话内嵌入式预览**：在回复末尾通过应用内预览指令呈现：
   ```
   ::preview{file="D:/Hermes/页面设计/prototype.html"}
   ```
   用户可在聊天窗口中就地体验交互效果并审查界面排版。

## 五、 检查核对清单

- [ ] 页面是否采用了有辨识度的主题配色，杜绝了千篇一律的紫色渐变？
- [ ] 文字排版阶梯是否反差鲜明，标题与正文字号区分清晰？
- [ ] 产物是否为自包含的独立 HTML 文件，未引入不可靠的外部构建依赖？
- [ ] 是否在回复中输出了标准的应用内预览标识？
