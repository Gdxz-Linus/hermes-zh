# OpenSpec 规格驱动开发实战引导指南（openspec-onboard）

## 概述

指导新接触 OpenSpec 的开发者或团队，通过一个微型、安全且真实的工程改动示例，完整演练一遍“需求探索 $	o$ 变更立项 $	o$ 技术设计 $	o$ 编码实施 $	o$ 验证核查 $	o$ 规格归档”的完整规格驱动开发生命周期。这不仅是一次概念宣讲，更是结合实际代码仓库开展的沉浸式实战教学。

## 适用场景

- “第一次在项目中使用 OpenSpec，希望能带我完整走一遍标准开发流程”
- “团队新成员入职，需要熟悉当前代码仓库的规格驱动开发规约”
- “快速了解 OpenSpec 的各项命令与核心工件的作用”

## 一、 启动前置环境检查

在开始引导前，首先检查本地是否已安装 `openspec` 命令行工具：

```bash
openspec --version
```
- 若命令不可用，立即阻断并给出安装指引：“当前环境未检测到 OpenSpec 命令行工具，请先完成安装后再开启新手引导模式。”

## 二、 教学实战六阶段标准演练

### 第一阶段：欢迎与理念导入
用通俗易懂的语言向用户阐明 OpenSpec 的核心价值：
- 为什么不直接写代码？因为“先定规格与验收标准，再动手编码”能够减少大部分无效返工；
- 明确演练规则：本次教学将在当前项目中挑选一个微小的真实改进项（如补全一段注释或添加一个无害的辅助函数），全程边做边讲解。

### 第二阶段：需求探索与确认
引导用户提出一个小需求，或主动建议一个微小的改进点：
- 演示如何将模糊想法梳理归纳为明确的输入；
- 确立第一个示例变更名称（如 `learn-openspec-workflow`）。

### 第三阶段：立项与全套工件生成
演示如何使用提议命令一步创建全套设计工件：
```bash
openspec new change "learn-openspec-workflow"
```
展示并逐一解释生成的三大工件：
- `proposal.md`：说明为什么要做；
- `design.md`：说明技术上怎么实现；
- `tasks.md`：说明具体的执行步骤是什么。

### 第四阶段：代码实施演练
演示如何严格根据 `tasks.md` 清单执行修改：
- 仅修改目标函数或文件；
- 运行代码测试验证修改是否生效；
- 演示将 `tasks.md` 中的复选框由 `[ ]` 勾选为 `[x]`。

### 第五阶段：完整性核查
演示如何执行核验命令，审查实现是否与工件完全契合：
- 检查所有任务项是否已勾选；
- 运行本地质量门禁测试。

### 第六阶段：规格合并与安全归档
演示如何优雅地收尾并结项：
- 将增量修改同步并入系统主规格；
- 运行归档命令将变更移入历史档案库：
  ```bash
  openspec archive "learn-openspec-workflow"
  ```
- 总结日常开发中应遵循的核心纪律。
