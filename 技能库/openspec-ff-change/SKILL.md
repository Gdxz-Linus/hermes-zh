# OpenSpec 变更工件快进生成指南（openspec-ff-change）

## 概述

指导在面对明确、紧急或小型的开发任务时，跳过单步交互确认的漫长等待，直接快速推进一次性生成从需求提议、技术设计到任务分解的全套工件，迅速进入代码编写阶段。

## 适用场景

- “需求非常明确，希望快速生成全套规格工件，不要一步一步问我”
- “快速推进变更的前期准备工作，立刻开始编码实现”
- “为小规模的缺陷修复建立轻量但规范的规格文档”

---

## 一、 核心操作流程

### 第一步：锁定变更名称与建设目标
- 提取用户请求中的变更名称与业务诉求；
- 若用户未提供明确目标，主动询问：“请简要说明您打算修改或实现什么功能？”并据此推导出规范的短横线命名（如 `fix-timeout-retry`）。

### 第二步：初始化变更物理目录
运行新建命令创建变更目录：
```bash
openspec new change "<变更名称>"
```

### 第三步：查询工件生成顺序并批量编写
运行状态检查命令获取所需的工件构建序列：
```bash
openspec status --change "<变更名称>" --json
```
按照返回的工件依赖顺序，不中断地一次性连续编写完成：
1. **`proposal.md`**：阐述变更动机与核心诉求；
2. **`design.md`**：确立技术方案与接口约定；
3. **`tasks.md`**：拆解具体的实施任务清单。

### 第四步：完成汇报与就绪确认
完成所有工件写入后，向用户汇报快进生成结果，并提示全套工件已就绪，可直接执行实施命令（`openspec-apply-change`）开始实施。

---

## 二、 检查核对清单

- [ ] 变更名称是否符合短横线命名规范，且能准确反映改动目标？
- [ ] 是否严格按顺序一次性生成了全套必要工件？
- [ ] 任务分解是否具体详实，具备清晰的验收条件？
