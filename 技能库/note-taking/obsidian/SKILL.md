# Obsidian 本地知识库笔记管理指南

## 概述

规范在本地文件系统中直接操作 Obsidian 知识库的标准工作流程。包括查找知识库路径、检索笔记文件、创建结构化 Markdown 文档、安全追加内容以及构建符合 Obsidian 规范的双向链接（Wikilinks）。

## 适用场景

- “在我的 Obsidian 笔记库中搜索包含某个关键词的文档”
- “根据当前讨论的技术方案，在知识库中新建一篇说明文档”
- “为现有的某篇笔记追加讨论结论，并关联到其他主题笔记”

---

## 一、 知识库路径解析与环境变量优先

在调用文件操作工具前，必须首先确定知识库的真实物理绝对路径：

1. **环境变量优先**：
   - 优先读取 `OBSIDIAN_VAULT_PATH` 环境变量（可在 `.env` 中维护）；
   - 若未显式设置，则默认检测用户主目录下的备选路径：`~/Documents/Obsidian Vault`（在 Windows 上对应 `C:\Users\<用户名>\Documents\Obsidian Vault`）。
2. **禁止在工具参数中原样传递环境变量**：
   - 内置文件工具（`read_file`、`write_file`、`patch`、`search_files`）不执行系统终端的变量展开；
   - 必须先在上下文解析出完整的物理绝对路径，再传入具体工具。由于知识库路径常包含空格，使用原生文件操作工具可彻底避免终端命令行转义异常。

---

## 二、 知识库文件检索与结构化阅读

1. **查阅指定笔记**：
   - 使用 `read_file` 工具传入笔记的绝对路径；
   - 相比终端命令，内置工具提供明确的行号定位与分页控制，便于对大型文档进行局部精读。
2. **全库文件列表列出**：
   - 使用 `search_files` 工具，设置 `target: "files"`，并在检索路径中传入知识库根目录；
   - 列出全量 Markdown 笔记时，设置匹配模式 `pattern: "*.md"`；
   - 如需查看指定子文件夹，则将目标路径限定在该子目录的绝对路径下。
3. **内容关键字检索**：
   - 使用 `search_files` 工具，设置 `target: "content"`；
   - 将搜索关键词或正则表达式填入 `pattern`，并指定 `file_glob: "*.md"`，快速缩小匹配范围并输出包含行号的上下文。

---

## 三、 笔记创建与结构化编辑

1. **新建笔记文档**：
   - 使用 `write_file` 工具直接写入完整 Markdown 内容，避免终端多行输入转义异常；
   - 笔记必须包含标准的前置属性头（Frontmatter YAML），用于标注文档元数据：
     ```markdown
     ---
     title: "笔记标题"
     date: 2026-10-21
     tags: [工程规范, 系统运维]
     ---
     ```
2. **定向安全修改与内容追加**：
   - **已有段落定位修改**：优先使用 `patch` 工具，依托上下文中唯一的标题或固定锚点行进行局部替换；
   - **文档尾部追加**：若存在稳定的末尾结构（如特定的分隔线或收尾引用），使用 `patch` 将原锚点替换为“原锚点 + 新内容”；
   - **全篇重构**：若修改跨越多处且逻辑高度分散，则先完整读取（`read_file`）后再调用 `write_file` 整体覆盖重写，避免拼接复杂的替换块。

---

## 四、 双向链接与知识图谱互联规约

Obsidian 使用双中括号语法建立笔记间的双向关联，在生成文档时应主动规范引用：

1. **基本双向链接**：
   - 语法：`[[目标笔记名称]]`（无需包含 `.md` 后缀）；
   - 示例：`关于底层通信协议的具体实现，请参考 [[网络后端架构设计]]。`
2. **别名显示链接**：
   - 语法：`[[目标笔记名称|自定义展示文本]]`；
   - 示例：`核心逻辑参照 [[系统全生命周期质量审查规范|质量审查规范]] 第四章。`
3. **锚点级局部定位链接**：
   - 关联到特定标题：`[[目标笔记名称#具体二级标题]]`；
   - 用于在大型技术文档中实现精准的章节跳转与事实溯源。

## 五、 自检核对清单

- [ ] 操作前是否已解析出真实的物理绝对路径，未直接向工具传递带有 `$` 符号的未展开变量？
- [ ] 笔记生成是否包含了规范的 YAML 属性头与标准的标题层级？
- [ ] 涉及知识关联时，是否使用了标准的 `[[文件名]]` 双向链接语法？
- [ ] 局部修改是否优先采用精确锚点的 `patch` 操作，保障上下文无损？
