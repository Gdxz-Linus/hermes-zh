# 桌面图形界面自动化与后台驱动指南（Computer Use）

## 概述

指导通过 Hermes 内置的 `computer_use` 工具，以**后台无干扰模式**直接控制操作系统的桌面应用程序与窗口。该机制不同于传统的模拟按键工具（如直接抢占鼠标光标或抢夺键盘焦点的方案），它允许在后台独立窗口中执行点击、文字输入与界面截屏，完全不打扰用户当前在前端编辑器的正常操作。

**核心准则**：
```
创建服务、开机启动项或终止用户正在运行的进程前，必须先获得用户明确肯定答复
```
凡涉及对系统全局状态产生持久影响的操作，助手严禁自行推断或擅自执行，必须向用户陈述操作理由并获得同意后再动手。

## 适用场景

- “在后台打开浏览器并完成一个特定网站的自动化表单填写与提交”
- “对指定桌面应用程序窗口截取当前画面，并识别界面中的按钮与输入框”
- “模拟在某个无命令行接口的桌面软件中点击指定菜单项”
- “自动化排查某个图形客户端的界面交互异常与弹窗状态”

---

## 一、 核心工作流程：四步标准交互循环

与桌面图形界面交互时，严格按照以下步骤推进：

```
第一步：捕获窗口状态（截取画面并提取带编号的组件清单）
  ↓
第二步：定位目标组件编号（依据返回的 #N 索引确认按钮或输入框位置）
  ↓
第三步：发送后台交互动作（针对 #N 发起点击、输入文本或按键操作）
  ↓
第四步：再次截屏核验（确认界面状态已按预期发生改变）
```

---

## 二、 常用动作指令范式

所有交互统一通过 `computer_use` 工具分发：

### 1. 窗口截屏与组件识别（首选第一步）
截取指定应用程序的窗口画面，并为界面上的所有可交互元素打上数字标号：
```python
computer_use(action="capture", mode="som", app="Chrome")
```
- 返回结果将包含当前画面的图片，并在文本中按行标出各组件：
  ```
  #1  按钮 '返回' 坐标: (12, 80, 28, 28)
  #2  文本输入框 '地址栏' 坐标: (80, 80, 900, 32)
  #7  链接 '登录' 坐标: (900, 420, 80, 24)
  ```

### 2. 针对指定编号组件发起点击
直接使用返回的 `#N` 编号作为目标标识，工具底层会自动计算其真实物理坐标并发送后台点击：
```python
computer_use(action="click", element=7)
```

### 3. 向输入框输入文本
针对指定编号的输入框注入文字：
```python
computer_use(action="type", element=2, text="https://example.com")
```

### 4. 发送键盘按键组合
发送特定的控制按键（如回车、Tab 切换或复制粘贴快捷键）：
```python
computer_use(action="key", key="Enter")
```

### 5. 页面或窗口滚动
在指定区域上下滚动视口以查看更多内容：
```python
computer_use(action="scroll", direction="down", amount=3)
```

## 三、 排障纪律与安全规范

1. **坚持编号驱动原则**：优先使用第一步捕获返回的组件编号（`element=N`），杜绝直接猜测屏幕硬编码绝对坐标，防止因窗口缩放或 DPI 差异导致点错位置；
2. **操作后必须重新捕获核验**：每次点击或输入后，不要假设操作必然成功；必须再次调用 `capture` 查看最新画面，确认页面是否已成功跳转、弹窗是否已关闭；
3. **敏感操作前置停顿**：当界面出现带有“支付”、“确认删除”、“重置系统”等高危弹窗时，必须立即停止自动交互，将当前截图与文字向用户呈现，请求用户确认后再决定是否点击。

## 四、 检查核对清单

- [ ] 是否首先执行了窗口捕获并获取了带编号的组件清单？
- [ ] 交互动作是否基于确凿的组件编号，避免了盲目猜测坐标？
- [ ] 关键操作后是否重新捕获了画面，确认了状态已真实更新？
- [ ] 遇到持久性系统配置或高危弹窗时，是否已向用户呈报确认？
