# OpenSpec 多项变更批量核验与归档指南（openspec-bulk-archive-change）

## 概述

指导对工程中多个并行推进且已经实施完毕的 OpenSpec 变更，开展集中的状态核验、规格冲突排查与批量安全归档。适合在阶段性版本发布或多个子模块改造集中结项时使用，大幅提升归档效率。

## 适用场景

- “当前有 3 个已完成的并行业务变更，需要一次性全部归档”
- “版本发布前夕，集中清点并归档所有已测试通过的历史改动”
- “批量整理活跃变更列表，消除已结项事项的视觉堆叠”

---

## 一、 核心操作流程

### 第一步：获取全量活动变更列表
运行查询命令获取当前所有处于活动状态的变更：
```bash
openspec list --json
```
若当前没有任何活动变更，向用户说明情况并安全退出。

### 第二步：多选确认待归档变更
向用户出示当前所有活动变更清单（包含各变更名称、任务完成比例与关联工作流程），并支持多选：
- 用户可指定具体变更列表（如 `change-a, change-b`）；
- 或选择“全部已完成的变更”。
- 严禁自行盲选，必须由用户明确选择勾选范围。

### 第三步：批量状态与完整性扫描
针对用户勾选的每一个变更，依次运行状态检查：
```bash
openspec status --change "<变更名称>" --json
```
- 汇总统计：将所选变更划分为“完全就绪可归档”与“存在未完成任务阻断归档”两组；
- 若某项变更存在未勾选的任务项，将其剔除出本批次归档列表，并明确说明原因。

### 第四步：排查规格潜在冲突并执行归档
- 若多个就绪变更修改了同一份主规格文档，智能检查其修改内容是否存在冲突，优先完成增量合并；
- 针对所有通过强校验的变更，批量执行物理归档命令：
  ```bash
  openspec archive "<变更名称>"
  ```
- 汇总输出本次批量归档成功的清单与被跳过的未完成清单。
