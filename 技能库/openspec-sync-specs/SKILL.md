# OpenSpec 增量规格同步与主干合并指南（openspec-sync-specs）

## 概述

指导将某项进行中或已实施变更目录下的增量规格说明（位于变更目录 `specs/` 下的局部修改），智能合并同步到工程主干全局规格说明书中。支持在暂不归档整个变更的前提下，保持主规格与最新代码设计同步。

## 适用场景

- “代码已实施并验证通过，需要将增量规格合并进系统的主文档中”
- “某项长链路变更需要分步将已完成的部分规格发布至全局文档”
- “更新主规格文档，使其反映最新的业务场景与接口约束”

---

## 一、 核心同步流程

### 第一步：选择包含增量规格的变更
- 运行变更列表查询命令，向用户展示当前包含增量规格目录（`specs/`）的活动变更：
  ```bash
  openspec list --json
  ```
- 由用户明确选定需要同步的变更名称。

### 第二步：检查变更环境与上下文约束
运行状态检查命令：
```bash
openspec status --change "<变更名称>" --json
```
- 若状态报告中包含 `actionContext.mode: "workspace-planning"`，说明当前处于跨工作区规划模式，暂不支持直接同步主干规格，应立即停止操作并向用户说明原因；
- 若为标准模式，解析出增量规格文件路径与主规格目标存储路径。

### 第三步：智能合并增量修改至主规格
本操作由智能体驱动执行智能合并，而非简单粗暴地全盘覆盖：
1. 读取变更目录下的增量规格文件（如 `changes/<名称>/specs/auth.md`）；
2. 读取主干对应的主规格文件（如 `openspec/specs/auth.md`）；
3. **精准合并差异**：
   - 若增量规格新增了具体场景或补充约束，将其插入至主规格对应章节下；
   - 若增量规格废弃或修改了原有规则，在主文档中更新对应条款并保持上下文完整；
   - 保持文档目录、术语与引用格式的严密统一。

### 第四步：核验并汇报合并结果
合并完成后，使用差异对比工具核实改动，向用户出示修改前后的关键段落对比，确认主规格已准确反映最新要求。

---

## 二、 检查核对清单

- [ ] 是否确认了当前变更包含合法的增量规格文件？
- [ ] 合并操作是否为基于语义的增量追加与精准修正，杜绝了暴力覆盖导致历史规格丢失？
- [ ] 合并后是否核对了主规格文件的目录层级与语法有效性？
