# 基于大模型的互联知识维基管理指南（Karpathy LLM-Wiki）

## 概述

指导构建与长期维护一个基于互联互通 Markdown 文档的个人或团队自增长知识维基。该模式借鉴了计算机学者 Andrej Karpathy 提出的知识维基架构思想：与传统的外部检索增强生成（RAG，每次查询时被动去外部数据源重新拼凑答案）不同，知识维基将阅读吸收的各类原始资料一次性编译提炼为高度关联、具备双向交叉引用的结构化知识条目，并随时间推移持续增量更新与自我修正。

**人机协同分工**：
```
由人把关资料源头并确定调研方向；由智能体负责阅读提炼、交叉引用、分类归档并维护全局一致性
```

## 适用场景

- “帮我基于当前研究的主题，在本地搭建一套成体系的知识维基”
- “将这篇论文或这篇长文章吸收整理进我的维基知识库中，并关联到已有概念”
- “检查当前知识维基中的死链接、孤立文档以及存在事实矛盾的页面”
- “针对我的维基知识库，回答一个需要综合多篇文档内容的高难度技术问题”

## 一、 知识库物理目录结构与三层架构

知识库的本地根目录优先读取环境变量 `WIKI_PATH`（可在 `.env` 中配置）；若未设置，默认在用户主目录下的 `~/wiki` 目录构建。

知识库由三个相互隔离又紧密配合的逻辑层级构成：

```
wiki/
├── SCHEMA.md           # 知识库结构规约、排版标准与领域配置
├── index.md            # 全局知识索引与各分类的一句话核心摘要速查表
├── log.md              # 知识增量操作日志（只追加，按年归档，记录每次录入的内容与时间）
├── raw/                # 第一层：不可修改的原始资料层
│   ├── articles/       # 网络抓取文章纯文本与页面剪藏
│   ├── papers/         # 学术论文 PDF 与核心摘要文本
│   ├── transcripts/    # 会议讨论纪要、采访录音文本
│   └── assets/         # 原始资料附带的图表与图片
├── wiki/               # 第二层：提炼加工后的互联知识页面
│   ├── concepts/       # 核心概念、基础理论与技术术语词条
│   ├── entities/       # 重点企业、开源项目、关键人物与模型
│   └── topics/         # 综合主题、架构演进对比与行业综述
└── queries/            # 第三层：高频与复杂综合查询的分析结论存档
```

## 二、 知识录入标准流水线（增量吸收四步法）

当用户提交一份新的材料（URL 链接、本地文档、论文或讨论记录）并要求收录时，按如下流程处理：

### 第一步：留存原始资料副本
1. 抓取或提取完整文本内容，存入 `raw/` 对应子目录下（如 `raw/articles/2026-10-21-smartdns-design.md`）；
2. 原始文件头部必须记录元数据：抓取时间戳、作者、来源出处 URL、文件 SHA256 校验和。**原始材料一旦保存，严禁后续擅自篡改**。

### 第二步：知识点提取与实体识别
阅读原始文件，识别出文章中涉及的：
- 核心定义与关键概念；
- 涉及的项目、工具或主体；
- 与既有维基页面的重合点与潜在事实冲突。

### 第三步：提炼并更新知识页面
1. **新建或增量更新页面**：在 `wiki/` 对应目录下创建或更新 Markdown 文档；
2. **规范建立双向链接**：使用标准维基语法 `[[目标页面]]` 与既有知识建立网状关联：
   - 示例：`该机制依赖 [[事件循环管理]] 确保在 [[Windows操作系统]] 下平稳退出。`
3. **标记事实冲突与版本演进**：若新资料指出了旧有结论的不足或修正，在页面中显式注明更新日期与修正依据，保留技术演进脉络。

### 第四步：更新全局目录与审计日志
1. **更新 `index.md`**：在对应分类下登记新增页面名称并附带一句话核心摘要；
2. **追加写入 `log.md`**：记录本次录入的时间、操作动作、输入文件与本次新建或修改的维基页面列表。

---

## 三、 基于知识库的深度问答与综合分析

当用户针对知识库提问时：
1. **优先检索本地目录**：通过 `search_files` 检索 `wiki/` 目录中的关键字与标签；
2. **沿着链接拓扑遍历**：读取核心命中的文档，并顺着文中的 `[[关联链接]]` 查阅上下文支撑材料；
3. **出具溯源严密的结论**：回答问题时必须明确指出结论引自维基中的哪一篇具体文档，确保每句话都有据可查。

---

## 四、 知识库健康体检与定期巡检

定期对整个知识库目录执行结构巡检：
1. **检查死链**：扫描所有文档中的 `[[目标链接]]`，核实目标文件在磁盘上是否真实存在；
2. **排查孤岛页面**：找出没有被任何其他页面引用的孤立文档，在相关主题页面中为其补齐交叉引用；
3. **索引完备性核对**：确认 `wiki/` 下的每一个有效文件均已收录进 `index.md` 目录中。

---

## 五、 检查核对清单

- [ ] 原始资料是否已妥善保存在 `raw/` 目录中并完整记录了来源出处？
- [ ] 知识页面是否采用了标准的 `[[关联文档]]` 双向链接语法？
- [ ] 本次录入是否已同步更新至 `index.md` 全局目录并在 `log.md` 中记录了审计日志？
