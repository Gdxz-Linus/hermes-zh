# 事实依据与来源引用核验技能（Grounded Citations）

## 概述

在撰写技术方案、事实排查报告、竞品对比与决策依据时，规范化为每一项外部获取的事实与数据建立行内编号引用与末尾来源对照清单。从根本上杜绝大语言模型的凭空虚构与虚假引用，确保所有交付结论均具备确凿、可验证的事实出处。

**核心铁律**：
```
严禁无据推论；涉及版本号、性能指标与客观事实，必须标注真实来源
```
严禁凭模型记忆编造不存在的网址或伪造引文数据；所有引用必须来自当次任务中实际调用网络工具、本地文件或官方接口真实获取到的原始文本。

## 适用场景

- 技术架构选型对比、第三方框架性能指标与参数上限评估；
- 编写正式技术方案、立项论证、研究报告或决策建议书；
- 涉及产品发布时间、版本更迭记录、官方策略变更等客观事实的核验；
- 多个不同信息源结论存在冲突时，需要逐项对比并溯源求证。

## 一、 来源引用三步标准流水线

### 第一步：实时登记检索来源（即查即记）
在调用检索工具（如本地 `free-search` 检索工具或内置工具）获取到网页、文档或接口响应时，**立即提取并记录该数据来源的元数据**：
- 来源标题（Title）
- 目标访问链接（URL）或本地文件绝对路径
- 原始文字片段摘录（字面事实原句，拒绝主观臆断改造）

### 第二步：正文撰写与行内编号映射（Cite While Drafting）
在陈述每一个需要事实支撑的关键论点、性能数字或版本结论后，**紧跟对应的方括号数字编号索引**：

```markdown
# 正文撰写示范：
DeepSeek-V4.1-Flash 采用了因果编码器-解码器架构，骨干参数规模为 5520 亿 [1]；其全局动态缓存开销降低至每个 Token 约 890 字节，约为早期版本的四分之一 [2]。根据 OpenAI 官方发布的模型说明文档，gpt-oss-120b 模型正式开源发布于 2025 年 8 月 5 日，并遵循 Apache 2.0 许可证授权 [3]。
```

### 第三步：文末统一附带来源依据清单（Sources List）
在回复或文档末尾，严格按行内引用的顺序，输出规范的来源列表：

```markdown
## 来源依据清单（Sources）
- [1] DeepSeek 官方发布公告：《DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression》 (https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)
- [2] DeepSeek 官方技术报告第 3 节：Attention Cache Compression Benchmark (https://arxiv.org/html/...)
- [3] OpenAI 官方公告：《Introducing gpt-oss》 (https://openai.com/index/introducing-gpt-oss/)
```

## 二、 事实核验与防错规则

1. **原文字面强校验**：
   - 报告中引用的关键数据（如显存占用 510GB、发布日期 2025 年 8 月 5 日），必须在抓取到的网页或文档文本中有完全一致的字面对应；
2. **区分“已验证事实”与“模型推论”**：
   - 对于经过工具检索并确证的事实，附带引用编号；
   - 对于基于物理常识推导但未在外部找到直接文献支持的逻辑分析，必须实事求是显式说明为“根据参数推导，尚未取得独立实测验证”，严禁假冒已验证事实；
3. **消除模糊概率词汇**：
   - 严禁使用“据说”、“可能已经发布”、“大概率”等轻浮推测，有据则据实陈述，无据则直接说明数据暂缺。

## 三、 自检核对清单

- [ ] 正文中的每一个具体数字与关键事实是否均有对应的编号标注？
- [ ] 文末来源清单中的链接与标题是否全部真实可查，未凭空编造 URL？
- [ ] 引用文本是否忠实于原文含义，未发生曲解或断章取义？
