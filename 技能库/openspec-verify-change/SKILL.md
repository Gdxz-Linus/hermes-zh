# OpenSpec 变更实施完整性核验指南（openspec-verify-change）

## 概述

指导在代码编写完成后，对照 OpenSpec 变更工件（需求说明、技术设计方案与任务清单），对实际代码实现进行全方位的完整性、正确性与一致性核验。确保所有规划的任务均已真实完成并通过测试，为归档变更提供确凿依据。

## 适用场景

- “代码已编写完毕，核验是否完整达成了最初的设计要求”
- “在归档变更之前，检查是否存在未完成的任务或遗留的缺陷”
- “核实增量规格修改是否与系统主规格保持协调一致”

---

## 一、 核心核验流水线

### 第一步：确认待核验的变更
运行状态列表命令，获取所有处于活动状态的变更，并让用户确认需要核验的目标：
```bash
openspec list --json
```
严禁主观盲猜，必须向用户明确显示变更名称与当前任务完成比例。

### 第二步：核查任务清单执行状态
读取目标变更的 `tasks.md` 文件：
- 逐项核对任务清单复选框；
- 如果仍存在未勾选的任务项（`[ ]`），必须向用户明确列出未完成项目，并提示完成前暂不建议归档。

### 第三步：三要素一致性核验
严格执行代码与文档的三要素对照检查：
1. **设计符合度**：核实代码实现是否遵循了 `design.md` 中的架构分层与接口约定；
2. **测试与真实验证**：在宿主真实运行环境中执行测试用例，核实退出码是否为 0，数据是否符合预期；
3. **文档与代码联动**：若涉及配置参数或公开接口修改，检查相关注释与说明文档是否已同步修改，杜绝文档脱节。

### 第四步：出具核验判定结论
根据核查结果出具明确的审核判定：
- **核验通过**：所有任务已勾选，真实测试全部通过，代码与规格完全吻合 $	o$ 建议执行归档命令（`openspec-archive-change`）；
- **存在偏差**：列出具体的不一致处、未完成任务或失败测试，提出明确修改建议。

## 二、 检查核对清单

- [ ] 任务清单中的所有复选框是否已全部确认为已完成状态？
- [ ] 是否在真实环境中运行了验证测试并拿到了确凿的成功输出？
- [ ] 是否核实了技术实现与设计方案的一致性，排除了遗留隐患？
