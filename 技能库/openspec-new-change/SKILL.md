# OpenSpec 新建变更目录指南（openspec-new-change）

## 概述

指导在工程中初始化一项全新的 OpenSpec 变更目录结构。确立变更名称、关联的工作流程模式，并生成初始的基础目录与说明文件模板，为后续逐步编写设计工件奠定基础。

## 适用场景

- “在项目中立项一个新的功能特性或修复任务”
- “为即将开展的代码修改搭建符合规格驱动开发的目录结构”
- “开始一个新的长链路复杂工程改造”

---

## 一、 核心操作流程

### 第一步：确认变更目标与命名
- 输入必须包含具体的变更描述或规范的英文短横线命名；
- 若用户描述宽泛，必须主动提问澄清：“请说明这项变更的目标是什么？”
- 依据业务目标提炼出精炼的短横线命名（如 `refactor-logging-pipeline`）。

### 第二步：确定工作流程规范
- 默认采用标准规格驱动工作流程（不追加 `--schema` 参数）；
- 仅当用户明确要求使用其他工作流程或询问可选工作流程时，运行查询命令展示：
  ```bash
  openspec schemas --json
  ```
  并按照用户指定追加 `--schema <规范名称>` 参数。

### 第三步：执行物理目录创建
运行新建变更命令：
```bash
openspec new change "<变更名称>"
```
命令会在工作区的规划主目录下自动生成该变更的专用目录与元数据文件。

### 第四步：引导进入工件编写阶段
创建成功后，明确告知用户目录已就绪，并引导用户进入下一步：
- 逐步编写工件：运行 `openspec-continue-change`；
- 或直接快进生成全套工件：运行 `openspec-ff-change`。

---

## 二、 检查核对清单

- [ ] 变更名称是否采用了清晰、小写的短横线命名？
- [ ] 是否在默认情况下选用了标准工作流程规范？
- [ ] 创建完成后是否给出了明确的下一步工件编写指引？
