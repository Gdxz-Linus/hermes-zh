# 电子邮箱收件箱分流整理与回复拟稿指南（Email Inbox Triage）

## 概述

指导对海量未读或混乱的电子邮箱收件箱进行系统性整理、分级筛选与事务分流。通过建立结构化判定队列，识别出需要立即应对的紧急事项、仅需知悉的通知类邮件与无价值垃圾邮件，并结合用户过往的真实行文风格，安全拟定得体的回复邮件草稿。

**核心红线纪律**：
```
默认仅执行“只读分析 + 拟定草稿”，严禁擅自直接发送邮件或永久删除邮件
```
用户提出“帮我处理收件箱”并不等同于授权代发邮件或清除邮件。助手在完成分析后，仅将拟定好的回复呈现为草稿，待用户亲自审阅并确认后再行投递。

## 适用场景

- “帮我梳理今天收到的邮件，有哪些需要我尽快回复或处理”
- “对当前收件箱进行一次性清零整理，按紧急程度分类呈现”
- “针对某封重要的商务洽谈邮件，模仿我平时的语气拟定一封回复草稿”
- “找出所有客户或供应商提出疑问但尚未得到解答的遗留邮件”

## 一、 邮件分流六级处理标准

对检索到的每一封完整邮件会话线索，严格归入以下六类处理矩阵之一：

| 分类标识 | 判定标准与业务含义 | 建议应对动作 |
| :--- | :--- | :--- |
| **紧急待办** | 包含明确的临近截止日期、阻断性故障、重要客户诉求、资金安全或高管直接指派事项。 | 立即置顶展示，优先起草回复并提醒用户确认。 |
| **常规答复** | 对方提出了具体的问题或协作请求，需要本方予以答复或提供信息，但无致命阻断性。 | 整理问题要点，在文末附带标准回复草稿。 |
| **无需回信但需跟进** | 邮件内容本身无需回信，但需要在外部系统中跟进落实（如会议审批、系统打卡、查阅账单）。 | 提取具体的行动事项，写入用户的待办清单。 |
| **等待对方反馈** | 用户此前已经回复过该邮件，当前处于等待对方反馈下一阶段进展的状态。 | 标注为“等待对方反馈”，无需用户操作。 |
| **仅供参考** | 业务通知、周报抄送或行业资讯，具备一定参考价值但无需任何后续操作。 | 归入参考档案，用户可直接批量标记为已读。 |
| **无用通知（Noise / Spam）** | 自动生成的系统广告、无意义推广邮件或无效机器推送。 | 建议直接批量归档，保持收件箱清爽。 |

## 二、 收件箱分流标准四步流水线

### 第一步：明确检索范围与安全边界
- 确定操作的目标邮箱账号、检索的时间窗口（如“最近 3 天”或“仅限未读邮件”）；
- 严格限定权限边界为只读与拟稿模式。

### 第二步：完整获取会话线索（Thread）
- 调度底层邮件工具（`google-workspace` 或 `himalaya`）拉取邮件列表；
- **通读完整上下文**：切忌仅凭最新一条短信息断章取义，必须阅读该邮件链条中的历史往来记录，防止遗漏前文中未解决的关键争议。

### 第三步：提取核心要素并分类定级
对每封重点邮件提炼以下要素：
- **发件人核心诉求**：对方究竟希望我方做什么；
- **明确截止时间**：对方要求的明确答复或完成时间；
- **历史已承诺项**：此前往来中本方已经答应的交付事项；
- **附件与补充材料**：邮件中是否附带了需要查阅的文档或合同。

### 第四步：拟定得体的回复草稿
在为重点邮件生成回复草稿时，必须保证语态符合正式职场规范：
1. **礼貌清晰**：开篇直接回应对方关切的核心问题，不绕圈子；
2. **行动明确**：说明具体的后续步骤与预估完成时间；
3. **保留原样待审**：将拟定好的草稿放置在独立代码块中，供用户一键复制或微调，并附带收件人与主题确认项。

---

## 三、 检查核对清单

- [ ] 是否保持了只读与拟稿原则，未在未授权时直接执行对外发送或删除？
- [ ] 邮件分类是否依据真实紧迫性客观划分，未遗漏紧急截止日期？
- [ ] 拟定的回复草稿是否准确回答了发件人的全部问题，且语句得体规范？
