# OpenSpec 单项变更完成与安全归档指南（openspec-archive-change）

## 概述

指导在某项变更的所有任务均已编码完成、真实测试验证通过且规格已合并之后，执行最终的安全归档操作。将已完成的变更目录自活跃列表移入历史归档库中，保持工作区活跃状态的简洁清爽。

## 适用场景

- “某项功能的开发与测试已全部结束，归档该变更”
- “完成了特定缺陷的修复并经过核验，正式结项归档”
- “整理活跃变更清单，将已完成的工作移入历史资产”

---

## 一、 核心操作流程

### 第一步：确认待归档的变更
- 运行列表查询命令获取所有当前处于活动状态的变更：
  ```bash
  openspec list --json
  ```
- 仅展示活动变更，由用户明确选择需要归档的目标变更名称。

### 第二步：工件完成状态严格前置强校验
运行状态检查命令：
```bash
openspec status --change "<变更名称>" --json
```
- **核心强校验门禁**：检查该变更的所有必要工件（proposal、design、tasks 等）状态是否全部被标记为已完成（`done`）；
- 检查 `tasks.md` 中是否所有任务复选框均已勾选（`[x]`）；
- **阻断原则**：如果仍存在未完成的工件或未勾选的任务，严禁直接归档！必须立即阻断并向用户报告未完事项，建议先完成实施与验证（`openspec-verify-change`）。

### 第三步：规格同步确认
- 检查该变更是否包含增量规格说明；
- 若包含增量规格但尚未合并至主干规格，提示用户：“该变更包含增量规格尚未同步至主规格，是否先执行规格同步？”在得到肯定指示后优先完成同步。

### 第四步：执行安全归档命令
在各项前置条件均完全满足后，运行归档命令：
```bash
openspec archive "<变更名称>"
```
系统会自动将该变更目录从活动工作区移入归档存储区（`archive/`），并更新全局活动索引。

## 二、 检查核对清单

- [ ] 是否强校验了所有设计工件均处于完成状态，且任务清单无遗留？
- [ ] 增量规格是否已成功合并至系统主规格说明书中？
- [ ] 归档执行后是否核实了活动列表中该变更已平稳移出？
