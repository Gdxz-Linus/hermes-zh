# 代码重构与精简技能（Simplify Code）

## 概述

对近期编写或修改的代码实施系统性的质量重构与结构精简。通过并发运行四个维度的专项审查视角，消除重复逻辑、展平多层嵌套、精简过多的条件分支判断，消除临时性修补代码，提高既有代码的可读性与可维护性。

**核心定位**：
- **这是一次代码整洁度提升，而不是寻找功能缺陷**。本技能用于改进那些已经能够正常工作的代码结构；排查业务逻辑漏洞与安全缺陷应调用 `code-audit` 或 `requesting-code-review`。
- **坚决拒绝过渡抽象**：重构的目的是让代码更直观易懂，严禁为了所谓的“设计模式”而人为引入不必要的工厂类、多层委托包装或虚设接口。

---

## 一、 重构必须遵循的三项铁律

1. **无测试保障绝不重构**：
   - 目标代码必须已有单元测试或全流程集成测试用例保护；重构修改仅变动代码结构，绝不改变外部业务行为。重构后全量测试必须 100% 保持通过。
2. **三层嵌套必须展平（优先使用前置条件检查并提前退出）**：
   - 嵌套层级达到或超过 3 层的 `if-else` 分支，必须在函数入口处先对不符合条件的异常分支进行前置判断并立即返回退出（Guard Clauses），避免业务核心代码陷入深层缩进中。
3. **单一职责与分支逻辑规模控制**：
   - 单个函数物理行数原则上不超过 50 行；
   - 单个函数的独立逻辑分支数量（即分支路径总数，对应学术上的环路复杂度指标）原则上不超过 10 个（即函数内的 `if`、`for`、`while`、`case` 等判断与循环分支累计不超过 10 处）。凡超过该阈值者，说明该函数承载了过多逻辑路径，极易漏测，必须将各独立业务逻辑提炼为专职的子函数。

## 二、 四维度并行审查视角

当用户要求“精简我的代码”、“重构近期修改”时，系统从以下四个独立维度并发分析代码：

### 维度 1：逻辑复用与消除重复（Reuse）
- 检索新写的代码中是否与现有模块存在重复逻辑；
- 检查是否存在相同的字符串常量、魔数或相同的正则表达式解析，提炼为统一常量或工具函数；
- 确认是否重复实现了标准库中已原生具备的算法或数据结构。

### 维度 2：代码质量与精简分支逻辑（Quality & Simplicity）
- **前置条件检查与提前退出（Guard Clauses）**：在函数开头先排除异常情况并返回退出，使主干业务代码在最外层清晰呈现；
  ```python
  # 改造前（嵌套过深，阅读负担重）：
  def process_transaction(tx):
      if tx is not None:
          if tx.is_valid():
              if not tx.is_expired():
                  # 核心业务
                  return do_process(tx)
      return False

  # 改造后（前置检查不满足即返回，主干逻辑清晰）：
  def process_transaction(tx):
      if tx is None or not tx.is_valid() or tx.is_expired():
          return False
      return do_process(tx)
  ```
- **消除含混命名**：将 `a`、`temp`、`data2` 等模糊变量更名为准确表达业务含义的自解释命名；
- **清理废弃残留**：移除调试用打印代码、已注释掉的历史废弃代码段。

### 维度 3：运行与内存效率（Efficiency）
- 消除循环体内部的不必要对象创建、多次重复正则编译与频繁的细碎内存分配；
- 检查是否存在不必要的数据全量复制（例如在大型数据集合上传递深拷贝而非引用或视图）；
- 对重复查询的数据结构，核验是否应当采用哈希映射替代列表的线性遍历。

### 维度 4：架构适切度（Altitude）
- 检查实现是否与所属模块的抽象层级保持一致；
- 底层通用工具模块中严禁硬编码上层业务系统的特定枚举值或业务文案；
- 消除过度设计的包装层，将一层无实质意义的原样转交函数直接内联消除。

## 三、 标准执行流水线

1. **锁定重构差异范围**：
   - 通过 `git diff` 或指定文件路径，精准界定本次需要精简的代码行，不扩散到无关文件。
2. **生成针对性重构建议**：
   - 逐项陈述重构位置（文件路径与行号）、当前结构存在的可读性或分支冗余问题，以及重构后的代码对比。
3. **分步实施与即时自验**：
   - 优先实施低风险的前置条件检查改造与死代码清理；
   - 每次局部重构后立即运行测试套件，确认修改未破坏任何功能契约。
4. **交付差异与成果陈述**：
   - 明确汇报减少了多少行冗余代码、消除了多少层嵌套，并给出回归测试全部通过的最终数据。
