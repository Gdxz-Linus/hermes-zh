# Python 交互调试与 debugpy 远程排障指南

## 概述

指导在终端命令行以及没有图形界面的远程服务器环境中，对 Python 应用程序进行深度调试。涵盖使用 Python 原生内置的 `breakpoint()` 与 `pdb` 终端调试器、通过命令行参数拉起程序，以及基于 `debugpy`（调试适配器协议，DAP）在服务正常运行过程中直接接入调试，或在程序意外报错崩溃时现场排查变量数据。

## 适用场景

- 单元测试运行报错，但控制台抛出的异常信息无法直接看清复杂对象中间是如何被改错的
- 在循环或递归逻辑中，需要实时观察数据列表或字典的内容变化
- 后台正在运行的服务或进程出现异常，但不能随意中断重启，需要直接接入排查
- 程序发生未捕获的报错崩溃时，希望程序直接停留在崩溃的那一行，现场检查当时的变量取值

## 一、 调试工具选择与梯队建议

根据问题排查的复杂程度选择最轻量的工具：

| 调试方式 | 核心适用场景 | 优势与使用方法 |
| :--- | :--- | :--- |
| **`breakpoint()` + pdb** | **本地快速调试首选** | 最轻量便捷。直接在源码目标位置写一行 `breakpoint()`，运行代码时就会在该行自动暂停并打开调试命令行。 |
| **`python -m pdb`** | 无需改动源码快速排查 | 用命令行参数直接拉起脚本并在第一行暂停，适合排查模块导入阶段的启动错误。 |
| **`debugpy` (DAP)** | 远程服务器或后台服务调试 | 允许外部调试客户端通过 TCP 端口，直接接入正在后台运行的常驻服务（如网关、后台工作线程）。 |

## 二、 `pdb` 常用命令速查对照表

在 `(Pdb)` 调试命令行下，常用控制指令如下：

| 命令 | 简写 | 真实动作与通俗解释 |
| :--- | :--- | :--- |
| `help` | `h` | **查看帮助**：查看调试命令说明（例如输入 `h b` 查看断点设置方法） |
| `next` | `n` | **执行下一行代码**：运行当前行代码；如果当前行调用了其他函数，直接执行完该函数并停在下一行，不跳入函数内部 |
| `step` | `s` | **进入函数内部**：如果当前行调用了其他函数，直接跳进该函数内部，从第一行代码开始逐行执行 |
| `return`| `r` | **执行到函数返回**：运行完当前函数剩下的代码，停在函数返回语句处 |
| `continue`| `c`| **继续运行**：让程序继续执行，直到遇到下一个断点或执行结束 |
| `where` | `w` | **查看调用链路**：自底向上显示当前函数是由哪一层代码调用的（调用栈信息） |
| `up` / `down` | `u` / `d` | **切换调用层级**：在调用链路中向上（上一层调用方）或向下（被调用方）切换查看上下文 |
| `print` | `p` / `pp` | **打印变量**：输入 `p 变量名` 查看内容；`pp 变量名` 可漂亮整齐地格式化输出复杂字典或列表 |
| `break` | `b` | **设置断点**：例如 `b 42` 在当前文件第 42 行设断点；`b 文件名:行号, 条件表达式` 可设置仅在条件满足时才暂停的条件断点 |
| `clear` | `cl` | **清除断点**：清除指定编号的断点（例如 `cl 1`） |
| `interact` | `interact` | **进入交互环境**：在当前代码位置直接启动完整的 Python 交互解释器，可任意导入模块或测试代码（按 Ctrl+Z 后回车或按 Ctrl+D 退出） |
| `quit` | `q` | **退出调试**：立即终止当前程序并退出调试命令行 |

## 三、 高频调试操作范式

### 1. 源码中直接添加物理断点（最常用）
在需要观察的代码行前直接加入：
```python
def process_data(payload):
    intermediate = transform(payload)
    breakpoint()  # <-- 程序执行到这一行会自动暂停，并交出调试控制权
    return finalize(intermediate)
```
- **提交代码前检查**：在将代码提交到 Git 仓库前，必须在工程中检索 `breakpoint()`，确认所有临时断点已经彻底删除：
  ```bash
  git diff | grep "breakpoint()"
  ```

### 2. 崩溃发生时直接停在现场（事后现场排查）
当运行某个脚本发生报错退出，但从报错文字看不出原因时，无需反复修改代码，直接带参数拉起：
```bash
python -m pdb -c continue path/to/script.py
```
- 程序一旦遇到未处理的异常，不会直接退出，而是会自动停在引发崩溃的那一行代码处；此时直接输入 `p 变量名` 即可现场检查崩溃时的变量真实取值。

### 3. 基于 `debugpy` 接入正在运行的后台服务
针对不能随意重启的后台服务或网关，在服务代码启动位置加入非阻塞监听：
```python
import debugpy

# 监听本地独立端口，不影响主流程继续执行
debugpy.listen(("127.0.0.1", 5678))
print("调试端点已就绪，正在监听 5678 端口...")

# 若需等调试客户端连接上后再开始运行，可调用：
# debugpy.wait_for_client()
```
外部编辑器或调试终端可以直接连接 `127.0.0.1:5678` 端口进行断点查看。
