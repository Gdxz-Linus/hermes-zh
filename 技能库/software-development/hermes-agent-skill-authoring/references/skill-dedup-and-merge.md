# 技能深层查重、融合扩充与词汇纯化指南

## 一、 为什么单看列表无法避免重复？

调用 `skills_list` 仅能返回技能名称、分类与一句话描述。仅凭名称判定是否重复存在严重缺陷：
1. **同义异名规避**：相同的技术能力完全可以冠以不同命名（例如已存在代码审计技能 `code-audit`，再次新建时可能会命名为 `vulnerability-checker` 或 `code-inspector`）；
2. **场景交叉**：某些垂直技能（如公文排版）其能力可能已被底层文档处理技能（如 `docx`）部分覆盖。

### 法定两阶段查重流程
1. **阶段一（列表粗筛）**：执行 `skills_list`，不仅快速比对名称，更要逐条扫描同分类下的 `description` 关键词；
2. **阶段二（正文精读）**：凡存在语义交叉可能性的既有技能，必须调用 `skill_view(name)` 完整阅读其正本章节与参考文档清单，核对具体步骤与支持能力；
3. **查重判定分支**：
   - **完全覆盖**：直接复用既有技能，坚决不建新技能；
   - **部分重叠**：执行下述“融合扩充流程”，将新规约追加至既有技能中；
   - **全新领域**：确认全库无同类能力，且具备跨会话高度复用价值，方可新建。

## 二、 外部技能引入与融合操作规约（Merge SOP）

从官方 Hub 或第三方社区引入技能时，严禁使用命令行直接安装未经汉化查重的技能：

1. **工作区暂存**：将外部技能下载至临时目录（如 `D:/Hermes/中文技能库/temp/`）；
2. **定位宿主技能**：在本地技能库中寻找功能最接近的宿主项；
3. **定向追加核心规则**：
   - 提取外部技能独有的参数矩阵、算法步骤或格式模板；
   - 使用 `patch` 动作，将新规则以独立小节形式写入宿主技能的 `SKILL.md` 或追加进 `references/` 目录；
4. **扩充触发标签**：在宿主技能的元数据中，将外部技能对应的场景关键词追加至 `description` 与 `tags`，确保单一技能入口即可响应多种触发提问；
5. **清理工作区临时目录**。

## 三、 翻译与词汇纯化排查标准

对重构或汉化的技能文件，必须严格杜绝英文直译带来的生硬表达与行业黑话，统一对照以下标准更正：

| 英文原词 / 生硬直译 | 规范地道的标准工程中文 | 优化说明与语境对照 |
| :--- | :--- | :--- |
| **Guard Clauses / 卫语句** | **前置条件检查（提前退出）** | 解释其本质是入口处排除异常条件并立即返回，主干逻辑保持外层展开。 |
| **Fragile command-line strings / 脆弱命令行** | **避免手动拼凑复杂的命令行文本** | 说明其原因是防止特殊字符、空格或换行转义失败导致执行异常。 |
| **Cyclomatic Complexity / 圈复杂度** | **独立逻辑分支数量控制（不超过 10 个）** | 明确其本质是单个函数内的判断与循环分支累计不超过 10 处。 |
| **CI is all green / CI 全绿** | **CI 全通过** | 简明干脆，消除程序员口语黑话。 |
| **Discussion thread / 讨论串** | **历史讨论记录** | 符合中文自然行文习惯。 |
| **Cognitive sediment / 决策沉淀在...** | **核心定论体现在...** | 消除互联网大厂空泛套话。 |
| **Robustness / 鲁棒性** | **容错与抗异常能力** | 消除非正式音译词汇。 |
| **Vague pronouns / 含混代词** | **模糊词语** | 杜绝使用“该文件”、“上述代码”等代称，改为必须指定明确文件路径。 |
| **Rollback / 彻底回滚** | **彻底还原** | 消除回滚行话，中文表达为执行还原、恢复原状。 |
| **Indentation corruption / 缩进损坏** | **防止格式错位** | 消除拟人生硬修辞，准确表达为避免缩进错误破坏配置结构。 |
| **Prompt cache / 前缀缓存** | **提示词缓存机制（Prompt Cache）** | 消除字面直译拼凑，准确表达大模型上下文缓存机制。 |
| **Judgement / 最终裁定** | **审查结论 / 判定结果** | 消除司法法庭用语，回归工程审查语境。 |
| **Commit hash / 提交哈希** | **代码提交版本号 / Git 提交 ID** | 消除底层哈希算法直译，贴合工程常规认知。 |
| **No code without failing test / 无失败测试不写业务代码** | **只有测试失败才编写修正业务代码** | 消除双重否定带来的逆向歧义，充要条件因果严密。 |
| **Red-Green-Refactor / 失败-通过-重构** | **核心“失败 - 通过 - 重构”三步循环** | 六字简明对仗，完全保留严谨有力的中文语境。 |
| **Hook / 钩子** | **拦截机制 / 拦截函数 / 拦截代码** | 消除早年计算机口语直译恶习，按其物理职能准确表达为在工具执行前后或网关层介入的拦截程序。 |
| **Align / 对齐（高频黑话滥用）** | **依据具体工程语境精准拆解（禁止万金油泛化）：**<br>1. 数值参数一致 $\to$ **“保持严格一致”**<br>2. 标准协议比对 $\to$ **“严格对照 RFC 官方表格”**<br>3. 上游代码借鉴 $\to$ **“参考官方实现 / 保持同步”**<br>4. 文档反映实测 $\to$ **“如实反映系统实际表现”**<br>5. 界面文字排版 $\to$ **“水平居中 / 靠左排列 / 靠右排列”** | 彻底消除大厂互联网黑话，坚决还原具体工程操作动词，杜绝用含混口号替代具体技术动作。 |
| **Inventory / 盘点（仓储黑话借用）** | **依据真实物理动作还原拆解：**<br>1. 代码行数/目录规模 $\to$ **“统计分析 / 遍历统计”**<br>2. 文件与磁盘大小 $\to$ **“空间占用统计 / 磁盘占用统计”**<br>3. 外部特性与支持项 $\to$ **“查阅支持清单 / 梳理可用列表”**<br>4. 阶段任务交付 $\to$ **“清点并核验交付成果 / 梳理完成情况”** | 消除把一切统计、核对、查阅统称“盘点”的模糊表达。 |
| **Output / 产出（套话动词化）** | **生成 / 产物 / 成果** | 文档或代码输出使用“生成”；避免将“产出”作为动词堆砌。 |
| **Blocker / 卡点（口语黑话）** | **问题 / 延误原因 / 受阻事项** | 消除口语色彩，严肃陈述阻碍进度的客观原因与遗留问题。 |
| **过度生硬造词与专有缩写硬翻** | **通俗直白命名（如 circular-flow 称“循环图”）；行业通用术语不画蛇添足（如“PDCA 循环”）** | 严禁生造晦涩词汇；本就众所周知的国际标准缩写保持原样，避免生搬硬套。 |
| **由用户拍板（口语黑话）** | **由用户决定** | 消除江湖气与口语套话，符合严肃书面技术文档规范。 |
| **走代理 / 不走代理（口语切口）** | **使用代理 / 通过代理连接 / 直连网络** | 消除随意口语，规范表述网络传输链路。 |
| **管道截断 / 管道接尾部截断（生硬直译）** | **使用管道把日志传递给 tail 命令，导致管道缓冲与输出延迟** | 讲清技术机理与后果，杜绝生硬直译。 |
| **时间正在推进（直译腔）** | **时间不断更新 / 持续更新** | 消除直译腔（progress / advance），符合自然汉语习惯。 |
| **内部调试随手记黑话（如“切一下就回落/又指向厂商”）** | **切换模型后系统未能维持选择，自动回退到默认接口或官方端点** | 杜绝仅个人理解的口语切口，必须完整陈述主客体与技术表现。 |
| **检查点归并（生造术语）** | **数据库执行检查点操作把日志写入数据文件** | 消除硬拼术语，清晰解释 WAL 与数据文件的交互机理。 |
| **断网心跳表（望文生义）** | **记录已退出进程的网关服务心跳表** | 消除乱猜直译，准确描述死进程残留心跳的本质。 |
| **截断运行日志文件（机械直译）** | **清空运行日志文件（把日志文件大小归零）** | 消除 truncate 的机械硬译，用明确具体的物理动作表达。 |
| **代码与设计类文档翻译（直译概念晦涩）** | **功能与意图优先于字面直译：**<br>1. 描述样式计算 $\to$ **“最终生效的计算样式”**<br>2. 描述样式层叠 $\to$ **“父级继承规则优先”**<br>3. 描述命令动作 $\to$ **“用大白话交代动作（如执行下一行）”** | 解决代码与设计类翻译难题，必须讲透底层物理动作，杜绝直接机械硬译英文参数。 |
| **Step over / Step into / Step out<br>（单步步过/步入/跳出，老教材机翻行话）** | **拆解为具体的通俗动作说明：**<br>1. next $\to$ **“执行下一行代码”**（不进入子函数内部）<br>2. step $\to$ **“进入函数内部逐行查看”**（跳进被调用的函数第一行）<br>3. out $\to$ **“执行完并跳出当前函数”**（执行完剩下的代码回到上一层） | 彻底消除堆砌“步”字的拗口行话，用大白话讲清调试动作。 |
| **Backtrace / Call stack<br>（调用栈回溯，生硬直译）** | **查看函数调用链路（Backtrace）** | 消除抽象字眼，解释清楚是“自内向外逐层列出当前函数是由谁调用的、完整执行路径是什么”。 |
| **Write-Ahead Logging / WAL<br>（与预写日志，不讲人话）** | **临时操作日志文件（`state.db-wal` / WAL）** | 讲清物理机理：“在数据库把数据真正写回主数据文件前，临时日志里完整保留着刚刚删除的数据”。 |
| **Checkpoint（检查点归并，生造词）** | **执行检查点操作（Checkpoint）** | 括号保留英文以对照 `PRAGMA wal_checkpoint` 命令，讲透机理：“把临时日志中的记录正式写回主数据文件并清空日志”。 |
| **Headless environment（无头环境，劣质直译）** | **没有图形界面的远程服务器或后台命令行环境** | 消除直译自 headless 的怪异词汇，讲清真实运行场景。 |
| **Dynamic attach & post-mortem<br>（动态附加与崩溃现场事后排查）** | **无需重启后台服务直接接入排查；程序报错崩溃时停在出错行，现场查看变量取值** | 杜绝概念罗列，拆解为通俗具体的排障动作。 |
| **单行变量打印即可查清，仅在复杂闭包时启动断点（大厂八股文）** | **如果只是简单查看变量内容，直接打印日志就能查明，不必大动干戈；只有在函数调用层级过深、外部无法打印，或多个任务并发难以理清时才使用断点** | 讲清选用原则的大白话依据，杜绝术语堆砌。 |
| **Applies atomically / 生硬机翻学究词汇** | **所有修改要么全部成功，要么全部放弃：只要其中任何一项操作出错，系统就会自动恢复原状，不会留下改了一半的残缺文件** | 讲清事务机理：人话就是要么全成要么全退，绝不留半截残破文件损坏原系统。但注意在涉及独立端口、测试实例与主环境完全分开的场景，“物理隔离”属于正规严肃技术用语，不可盲目扩大化当成黑话抹杀。重点在于源头语境化精准翻译，绝不在死板的替换表里搞一刀切替换。 |
| **Character budget / 字符预算 / 致字符预算超限（大厂套话借用）** | **超出字数上限 / 超出记忆容量上限 / 在最大字数限制内** | 消除把字符限制称为“预算”的大厂套话，回归规范直接的字数容量表达。 |
| **Drive real headless / 驱动真实无头（极具迷惑性的怪异机翻）** | **在后台运行真实的网页浏览器执行自动化网页交互** | 彻底消除“真实无头”怪异机翻，准确说明是在后台静默执行浏览器交互。 |
| **中文主用词汇后挂不必要的普通英文原词（如 检查点(Checkpoint)、空闲数据页(Freelist Pages)）** | **中文概念已完整独立时直接使用纯中文表述，仅保留标准代码命令、协议缩写或作为反面示例** | 区分代码参数对照与正文行文，杜绝字字挂英文原词的机器直译残留。 |

## 四、 核心原则：专业术语英文标识与通俗中文解释的辩证关系

用户明确强调：**“翻译的不好，不是删英文！”**

在审查与翻译技术文档时，严禁走到“看到英文就机械一删了之”的虚无主义极端：
1. **保留必要英文对照**：对于系统命令参数、数据库 PRAGMA 指令、文件后缀或国际通用缩写（如 `Checkpoint`、`WAL`、`Backtrace`、`CDP`、`DAP`、`MSIX`），在首次定义或参数对照表中**必须自然带上括号英文**，便于排查时与系统日志或命令行交互进行精准交叉验证；
2. **中文必须讲透机理说人话**：核心病因绝不是括号里带了英文，而是**中文翻译本身生硬拗口、缺乏常识、脱离机理**。中文正文必须主谓宾完整，把底层发生了什么用普通人第一遍就能看懂的话交代清楚，坚决杜绝生搬硬套老旧机翻词。

## 五、 工具（Tools）汉化与维护安全规约（动说明、不动名字）

工具是大模型的物理执行器（底层 Python 函数），汉化工具时必须严格遵守如下红线：
1. **函数名与参数名绝对禁止改动**：
   - 工具名（`name`，如 `read_file`、`terminal`）与参数键名（如 `path`、`command`）是写死在底层 Python 代码中的接口，改动会导致系统报 `找不到函数` 错误；
2. **仅汉化功能描述（Description）与参数解释**：
   - 将 `description` 与 `parameters.*.description` 改写为通俗标准的工程中文，提升大模型理解与填参准确度，消除模型思考时的英文诱导源；
3. **工作区目录层级与原版镜像保持一致**：
   - 本地工作区工具库（`D:\Hermes\中文工具库\`）必须严格按照原版目录（如 `tools/file_tools.py`、`tools/terminal_tool.py` 等）组织，严禁扁平堆叠；
4. **单点精准替换，严禁大段切片覆盖（防调度断裂铁律）**：
   - 替换工具 Schema 时，**严禁使用粗糙的大段源码切片截取**，防止误删函数末尾的底层调度函数（如 `is_bridge_tool`）或模块导入语句（如 `from tools.registry import registry`）；
   - 必须使用唯一的字面值字符串执行精准单点替换（`replace`），绝不触碰函数声明与上下文结构；
5. **小步快跑与真实 import 双重强校验**：
   - 严禁一次性大面积修改代码，必须分小批推进（每批 5 至 8 个）；
   - 单文件 `py_compile.compile()` 仅能检查静态语法，无法捕获未定义变量；写盘后**必须编写脚本执行真实的 `import tools.xxx` 动态加载测试**，彻底杜绝 `NameError` 导致后台服务启动时闪退；
   - 关键工具修改后必须运行 `hermes doctor` 真实通过全系统数十项诊断测试；
   - 必须出示中英文逐字对照表交用户审阅，获得明确确认后方可安全固化；
6. **应急恢复命令优先使用 Python 标准库**：
   - 遇到故障需要向用户出示修复命令时，严禁使用依赖特定终端语法的指令（如 PowerShell 的 copy 实际上是 `Copy-Item` 的缩写，不支持 `/y` 参数，且会把 `HEAD~1` 的波浪号误展开为用户主目录导致命令报错）；
   - 优先出示跨平台跨终端 100% 兼容的 Python 脚本命令（如 `python -c "import shutil; shutil.copyfile(...)"`），彻底避开 CMD 与 PowerShell 的符号和参数差异；
7. **PowerShell 7 启动崩溃已知缺陷防范**：
   - 当终端窗口较窄时，PowerShell 7.4.x 启动时计算版本更新通知横幅右侧宽度会得出负数 `-17`，引发 `ArgumentOutOfRangeException: totalWidth ('-17') must be a non-negative value` 导致进程直接被操作系统强行退出终止；
   - **彻底解决手段**：向用户系统环境变量中写入 `setx POWERSHELL_UPDATECHECK Off`，彻底关闭启动时的版本更新检测横幅；
8. **阶段性词汇纯化规范补充**：
   - **工作流程**：替代生硬直译缩写，恢复自然规范的书面汉语表达；
   - **全流程**：替代口语泛化用语，准确描述工程处理路径与测试范围；
   - **直接可用与原生就绪**：替代老教材直译腔，规范描述技术特性；
   - **自我改进**：保持极简两字，严禁拖带多余修饰或冗长啰嗦用语；
   - **背景资料**：准确传达辅助上下文意图，避免机械误译；
   - **用户档案**：消除虚浮套话，回归规范朴素的工程中文；
   - **文件交付附件（拒绝文件卡片机翻）**：系统生成带下载与预览按钮的文件条目属于文件交付附件或可下载文件条目，严禁无脑机翻为“交付文件卡片”或“文件卡片”；
   - **卡片多场景语义还原**：英文 card 词义宽泛，严禁泛化直译。架构图中译为“组件节点”，演示排版中译为“分栏内容区块”或“要点列表框”，模型文档中译为“模型技术说明文档”，知识库中译为“结构化知识条目”，看板任务中统一译为“任务条目”，金融账务中明确写为“信用卡”或“支付卡”；
   - **文档内嵌代码与变量名零触碰铁律**：修改带有代码示例的 Markdown 文档时，仅允许修改注释文字，代码变量名（如 `card_width`）必须分毫不动，防止造成变量未定义崩溃；
   - **三层代码完整性校验流程**：交付前必须执行 AST 抽象语法树解析、YAML 动态变量（如 `{reason}`, `{session_id}`）守恒校验、反向特征词检索清零与英文原版双向对比审查，确凿证实代码零损坏；
   - **hook 依技术动作与语境精准还原**：在命令/工具拦截场景译为“插件拦截”或“拦截代码”；在插件扩展接口计数时译为“扩展点”（如“个扩展点”）；在网关事件生命周期与通配订阅时译为“事件回调”或“订阅……事件”；在 shell 外部脚本时译为“shell 回调脚本”，杜绝生硬机械翻译；
   - **placeholder 依所指具体对象精准还原**：历史消息/工具输出截断替换时译为“简短提示”或“简短标记”；文件读取去重时译为“一段简短说明，不再重复内容”；环境变量与模板参数替换时译为“变量引用”或“模板变量/变量名”，杜绝统一机械直译；
   - **budget 依具体计量对象精准还原**：对话轮次上限时译为“最多 N 轮 / 轮次用尽”；迭代限制时译为“迭代上限”；单回合耗尽时译为“迭代次数或成本额度已用尽”；文本压缩篇幅分配时译为“摘要篇幅”；终端资源监控面板（如 TUI 的 token 计数面板）译为“用量”；仅在真实财务收支场景保留“经费开支计划”，严禁将一切限制或配额机械翻译为财务词汇；
   - **headless 依运行形态精准还原**：浏览器后台静默运行场景一律规范表述为“后台运行的浏览器”或“后台运行的 Chromium”，杜绝怪异字面机翻；
