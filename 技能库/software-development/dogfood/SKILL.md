# Web 应用探索性测试与缺陷取证指南（Dogfood QA）

## 概述

规范使用浏览器自动化工具对 Web 应用程序进行系统性探索性质量保证测试（QA Testing）的标准流程。模拟终端用户的真实操作路径，主动探查界面死链、交互异常、表单校验疏漏与前端未捕获异常，并生成包含复现步骤、控制台日志与关键截图的结构化缺陷报告。

## 适用场景

- “对新部署的 Web 服务做一次完整的功能巡检与冒烟测试”
- “模拟用户登录、加入购物车、结算的全链路交互，排查是否存在页面停止响应的问题”
- “测试表单在极端非法字符与超长输入下的容错表现”

---

## 一、 探索性测试五阶段标准工作流程

```
第一阶段：范围规划（确定测试入口、核心链路与证据存储路径）
  ↓
第二阶段：深度探索（页面加载、DOM 解析、控制台静默异常捕获、交互操作触发）
  ↓
第三阶段：确凿取证（捕获完整堆栈、网络状态码与界面报错截图）
  ↓
第四阶段：定级分类（依据业务影响严重程度划分为 P0 至 P3）
  ↓
第五阶段：报告交付（输出结构化缺陷分析与修改建议表）
```

---

## 二、 各阶段详细操作标准

### 1. 第一阶段：范围规划
- 明确测试根路径（如 `http://localhost:3000` 或外部测试域名）；
- 梳理需要覆盖的核心业务矩阵：
  - 核心展示区（主页、导航条、侧边栏、页脚链接）；
  - 关键操作主链路（注册、鉴权登录、核心表单提交、数据筛选）；
  - 边界异常状态（空数据状态提示、404 页面、无权限访问提示）。

### 2. 第二阶段：深度探索与异常捕获
对链路中的每一个关键页面与核心组件执行如下标准动作：
1. **页面导航与加载确认**：驱动浏览器打开目标 URL，等待网络空闲与 DOM 树构建完成；
2. **DOM 结构与元素提取**：获取当前页面的交互组件清单（输入框、操作按钮、下拉选择框）；
3. **控制台静默报错排查（高价值项）**：
   - 每次页面跳转后与每次关键交互动作后，必须主动调取浏览器控制台输出；
   - 界面看似正常但控制台抛出 `TypeError: Cannot read properties of undefined`、`Uncaught Promise Rejection` 等隐蔽错误属于高危技术隐患，必须全量记录；
4. **表单极值与边界探索**：
   - 测试必填项校验：直接留空提交，检查是否有明确友好的红字提示；
   - 测试非法格式输入：如邮箱字段输入中文、电话字段输入特殊符号；
   - 测试极端长度输入：输入超长字符串（1000 字符以上），检查排版是否发生文字溢出破坏布局。

### 3. 第三阶段：确凿取证
每当发现任何功能异常或样式崩塌时，严禁使用模糊语言定性，必须收集三项硬证据：
1. **精准操作路径**：记录从哪个页面、点击了哪个具体组件（标注按钮文字或选择器）触发；
2. **控制台与网络层证据**：记录完整的异常调用堆栈与失败的接口响应状态码（如 500 Internal Server Error）；
3. **现场截图存证**：截取当前界面的异常画面并保存至报告目录。

### 4. 第四阶段：缺陷定级标准

| 缺陷等级 | 判定标准 | 示例 |
| :---: | :--- | :--- |
| **P0（阻断级）** | 核心主流程完全中断，页面停止响应、白屏或数据发生丢失。 | 登录按钮点击无响应，结算页面完全白屏崩塌。 |
| **P1（严重级）** | 关键功能不可用，且当前没有可替代的临时绕过路径。 | 搜索筛选条件完全失效，分页按钮点击无反应。 |
| **P2（常规级）** | 次要功能异常，或存在较为繁琐但可行的临时替代手段。 | 控制台存在静默 JS 报错、表单格式错误提示文案不准确。 |
| **P3（微小级）** | 界面排版错位、文字溢出、缺少暗黑模式适配等纯外观瑕疵。 | 按钮内文字折行、局部边框未居中等排版瑕疵。 |

### 5. 第五阶段：报告结构化交付
最终交付的报告必须包含：
- **测试执行概览**：测试覆盖的页面数、执行的交互动作总数、耗时；
- **缺陷统计矩阵**：按 P0/P1/P2/P3 分布的数量汇总；
- **缺陷详情明细表**：包含“缺陷标题 + 影响等级 + 复现步骤 + 实际表现 vs 预期表现 + 现场证据 + 建议修复方向”。

- [ ] 发现缺陷时是否记录了完整的复现路径并保存了具体证据？
- [ ] 缺陷等级评定是否依据对业务流程的实际阻断程度客观划分？
