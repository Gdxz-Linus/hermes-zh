# 面向使用者的发布说明（Release Notes）

发布说明随版本对外发布，读者是不看代码的使用者。它回答两个问题：这次修好了我会碰到的什么麻烦；升级后我的配置会不会变。

## 一、章节结构

```
### 概述
一两句：修了多少个问题、分几个方面、升级要不要改配置、有几处行为变化。

### 解析正确性 / 服务稳定性 / 安全加固 / 配置行为
按“使用者能感知的后果”分类，不按代码模块分类。
每条格式：**加粗一句话说清修好了什么。** 再说此前会碰到什么现象、现在是什么行为。

### 升级须知
只写会改变既有配置行为的那几项，逐条给出“旧行为 → 新行为 → 用户该做什么”。

### English
与中文逐段对应，不是机器直译。
```

不写“规模与验证”节。测试数量、文件数、增删行数属于工程内部度量，使用者不关心。

## 二、用语红线

**保留**（使用者本来就懂的项目专有术语与参数名）：
双栈、上游、TTL、ECS、缓存、预取、否定缓存、DoQ、DoH、DoH3、QUIC、HTTP/3、ALT-SVC、SERVFAIL、NOERROR、SOA、ipset、nftset、netlink、DHCP、mDNS、ICMP，以及所有配置参数名（`domain-rules`、`bind-cert-file`、`max-reply-ip-num`、`audit-num`、`log-filter`、`resolv-file`）。

**必须换掉**（程序员视角，使用者读不懂）：

| 禁用写法 | 改为 |
| :--- | :--- |
| 侧信道 | 耗时随长度变化，可被用来推测口令 |
| 整数下溢 / 越界 | 长度校验缺失（畸形报文会被拒绝） |
| 符号链接 | 软链接 |
| 栈回溯 | 一大段程序报错信息 |
| 死配置 / 未被消费 | 配置了也不起作用 / 当前未被支持 |
| 空转 | 持续占用一个处理器核心 |
| 夹取 / 钳制 | 取上限 |
| 挂载（中间件） | 启用 |
| 临界区 | 合并为一次操作 |
| 套接字 | 连接 |
| 抹除 / 吞掉 | 丢弃 |
| 误杀 | 误判失败 |

《行话参照表》里的词同样禁用。清单以 SOUL.md 为准，不在此处重列，避免两处不一致。

## 三、术语统一：先查文档站，不得自创

同一概念在项目文档站里已有固定说法时，发布说明必须用同一说法。典型：域名层级统一写「**主域名／子域名**」，不写「父域／子域」。自创说法会让文档站与发布说明互相矛盾，用户对照两处会发现不一致。

做法：动笔前先在文档站 `grep` 该概念的候选说法，看哪个出现次数最多、出现在正式章节里。英文侧用对应的标准表述（`parent domain` / `subdomain`）。

## 四、修复数量必须按版本边界统计

错误做法：只统计最近一轮审查的条目。上一发布标签之后可能还有一批已提交但未发布的修复，它们同样属于本次发布。

正确口径：

```bash
# 1. 上一发布标签之后到 HEAD 的提交
git log --oneline v<上一版本>..HEAD
# 2. 工作区未提交改动
git diff --stat
# 3. 逐条对应台账条目，扣除“误报不改”的
```

发布说明里的数字与台账里“已完成”的条目数必须对得上。用户会当场核。

## 五、中英文同步

英文不是中文的逐字翻译，而是同一内容的英文表述。两侧条目数必须逐段相等。核对方法：

```bash
# 中文各节条目数
awk '/^### 解析正确性/,/^### 服务稳定性/' RELEASE_NOTES.md | grep -c '^- \*\*'
# 英文各段分号分句数（应与中文条目数相等）
```

## 六、交付前自检

```bash
# 内部说法残留（必须全为 0）
grep -cE '批次|编号 [0-9]|P[0-3] |审查' RELEASE_NOTES.md
# 代码语言残留（逐个查，必须全为 0）
for w in 套接字 临界区 侧信道 整数下溢 符号链接 栈回溯 死配置 抹除 误杀 空转 夹取 挂载 消费 硬编码 恒定时间; do
  c=$(grep -c "$w" RELEASE_NOTES.md); [ "$c" != "0" ] && echo "$w: $c"
done
# 工程度量节（必须为 0）
grep -c '规模与验证' RELEASE_NOTES.md
```

## 七、常见返工原因

- **满篇代码语言**：把根因分析直接搬进发布说明。根因属于审查报告，发布说明只写现象与结果。
- **保留了工程度量**：以为用户会关心“测试全绿”。用户不关心，只关心能不能用。
- **数字口径错**：只算了一轮审查。
- **术语自创**：没查文档站就自己造词。
- **漏写升级须知**：行为变化没单列，用户升级后当成故障。
