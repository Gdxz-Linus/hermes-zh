# 中文会议纪要与行动清单整理技能

## 概述

将原始会议录音转写文本、散碎发言记录或草拟会议笔记，系统性提炼为结构严肃、权责清晰、具备执行力的标准**会议纪要与督办行动清单**。

**核心铁律**：
1. **严格区分“研讨过程”与“明确决议”**：脑力激荡、个人观点陈述或存在争议未定事项，严禁当作最终决策记录；
2. **严禁凭空指定责任人与时限**：发言中未明确指定承办人或截止日期的事项，统一如实标注为 `待明确`，绝不凭空指派；
3. **事实出处可溯源**：每项决策与分工均需附带原始发言人或记录定位，保证材料可核验。

---

## 一、 会议纪要四段式标准结构

整理中文正式会议纪要时，必须按以下四个核心模块组织内容：

### 1. 会议基本要素模块（要素完备）
- **会议名称**：如“关于智能体平台架构改造专项推进会”；
- **基本信息**：时间、地点（或线上会议链接）、召集人/主持人、出席部门与人员、列席人员、纪要记录人。

### 2. 会议议题与研讨背景
- 简明说明本次会议召开的核心目标；
- 列举主要审议或研讨的技术方案、业务议题或专项报告。

### 3. 会议主要议定事项（核心决议）
按议题逐项归纳会议达成的正式共识，段落采用“会议认为……”、“会议决定……”、“会议要求……”等庄重语气开门见山陈述：
- **议定结论明确**：陈述方案是否原则通过、采纳了哪套实施路径；
- **分歧处理明确**：若某项议题暂未达成一致，明确记录搁置原因与后续再议机制。

### 4. 任务分解与督办责任清单（Action Items）
将所有落实决议的具体工作，以结构化表格形式逐一分解。

---

## 二、 督办行动清单要素规范

提取的每一项具体任务，必须完整包含以下六个维度的要素：

| 要素字段 | 填写规约与判定准则 |
| :--- | :--- |
| **任务编号** | 统一采用编号标识（如 `ACT-01`、`ACT-02`）。 |
| **具体任务描述** | 明确陈述要做什么具体工作，交付什么形态的产物，拒绝含混主题。 |
| **主办部门 / 责任人** | 记录发言中明确点名的负责人；未明确人员时记录为 `待明确`。 |
| **完成截止时间** | 明确约定的物理日期（如 `2026-11-15 前`）；未指明则填 `待明确`。 |
| **前置依赖条件** | 该任务启动前需要其他部门提供的输入或支撑。 |
| **原始发言出处** | 标注该项分工源自谁的提议或具体转写记录位置。 |

```markdown
# [会议名称] 纪要

**会议时间**：2026年10月20日 14:00 - 15:30

**主 持 人**：张三（技术总监）  
**出 席 人**：李四、王五、赵六、技术部全体骨干  
**记 录 人**：系统记录助手  

---

## 一、 会议主要议定事项

### （一） 关于模型推理节点架构改造
会议听取了关于采用 8 卡 H200 部署全量 DeepSeek 模型的方案汇报。会议认为，采用该方案能有效降低长上下文推理延迟，会议原则同意该实施方案。会议明确，必须严格执行多卡显存保护参数，严禁超载运行。

### （二） 关于办公与开发技能中文化推进
会议讨论了现有自动化技能的中文化重构工作。会议决定，先行对开发与文档处理等 6 个核心技能完成精准汉化，并在宿主环境完整备份原英文工程文件，确保生产业务无缝衔接。
```

## 四、 拟稿自检核对清单

- [ ] 是否已剔除参会人员头脑风暴中的非定论建议，仅保留正式议定决议？
- [ ] 针对发言中未指定负责人或未给出时限的事项，是否如实填写了“待明确”？
- [ ] 行文是否做到了结论先行、主谓宾完整，杜绝了口语与网络流行语？
- [ ] 行动项表格中的各项任务是否均具备明确的交付标准？
