# 商品与差旅价格监控追踪指南（Price Monitor）

## 概述

指导对特定可购买商品、机票航线、酒店房源或门票库存进行自动化价格追踪与低价提醒。规范处理商品型号规格差异、税费与运费、币种换算、实时库存状态以及重复提醒防打扰机制。初始化配置在交互前台完成，周期的自动化轮询检查则交由计划任务（`cronjob`）调度执行。

## 适用场景

- “监控这款笔记本电脑的价格，当降到 6000 元以下时立刻提醒我”
- “追踪下个月从北京飞往东京的往返机票，只要出现低于 3000 元的票价就发通知”
- “关注某酒店的特定房型，一旦有可全额退款的空房立即告知”
- 配合定时任务定期抓取目标页面，更新价格历史曲线并判定是否达到报警阈值

---

## 一、 初始化配置三步标准流程（前台一次性执行）

严禁在未经验证的情况下盲目建立定时轮询任务，必须严格按以下顺序实施：

### 第一步：明确目标商品与具体规格（定义监控标的）
记录完整的商品特征，确保不会与同型号其他规格产生混淆：
- **来源与链接**：商品官方链接、平台标识、商品 ID；
- **具体规格配置**：颜色、存储容量、版本（如国行/海外版）、成色（全新/二手）；
- **差旅与酒店特定维度**：航班号、出发到达日期、舱位等级、退改签规则；
- **允许的替代项**：是否接受特定范围内的同类替代配置。

### 第二步：设定清晰的报警阈值与触发条件
确立没有歧义的报警判断规则：
- **货币与最终到手价**：明确计价币种（CNY / USD 等）、是否包含增值税与预估运费；
- **目标触发阈值**：设定明确的触发数字（例如“总价 $\le$ 4999 元”）；
- **库存与售后要求**：例如“必须为有现货可发状态”、“必须支持无理由退货”；
- **通知静默冷却期**：设定触发一次提醒后，在多少小时内不再针对同一价格重复推送打扰用户；
- **通知送达目标**：明确提醒推送到终端会话、桌面通知还是特定通讯渠道。

### 第三步：前台真实抓取验证并固化监控契约
1. 在交互前台使用 `web_extract` 或驱动真实浏览器 `browser_exec` 对目标链接发起一次真实抓取；
2. 提取并记录当时的基准观测数据：抓取时间戳、当前标价、税费运费、库存状态；
3. **编写本地监控契约文件**（写入 `$HERMES_HOME/price-watches/<标识>.json`）：
   ```json
   {
     "slug": "laptop-thinkpad-x1",
     "target_url": "https://example.com/product/12345",
     "currency": "CNY",
     "target_price": 5999,
     "baseline_price": 6499,
     "last_checked": "2026-10-21T18:00:00+08:00",
     "status": "watching"
   }
   ```
4. **调度后台定时任务**：
   在前台首测成功后，创建定时任务定期执行轮询：
   - 抓取频次必须尊重目标站点的防爬与访问限制，通常建议设为每 6 小时或每天一次，严禁设置分钟级高频请求；
   - 任务指令中加载本技能并传入契约文件路径。

---

## 二、 周期轮询检查与触发决策（后台定时执行）

定时任务触发时，执行以下自动化决策逻辑：
1. **读取契约**：加载对应的 JSON 监控契约文件，获取上次记录的基准数据；
2. **抓取最新数据**：获取目标页面的最新到手价格与库存状态；
3. **阈值判定**：
   - 若最新价格 $\le$ 目标价格，且符合库存与退改要求，且当前已超出静默冷却期 $	o$ **触发低价通知**；
   - 若未达到触发条件 $	o$ 仅更新契约文件中的最后检测时间与当前价格，静默结束，不打扰用户；
4. **异常处理**：若目标页面出现 403 阻断或人机验证，记录失败次数，连续失败 3 次以上时生成任务异常排查提醒。

---

## 三、 检查核对清单

- [ ] 监控标的是否已锁定确切的型号、规格与版本，杜绝了歧义？
- [ ] 报警规则是否明确了到手总价（含税费运费）与币种？
- [ ] 是否在前台成功完成了首次真实页面抓取，核验了数据提取链路？
- [ ] 定时任务调度频率是否合理，避免了对目标站点的高频轰炸？
