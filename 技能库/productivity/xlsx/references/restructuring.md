# 引用感知的结构调整（xlsx_restructure.py）

`scripts/xlsx_restructure.py` 执行一次插入或删除行列，并把所有引用被移动单元格的地方改写到正确位置。本文件给出确切的改写规则与诚实的边界。

## 会被改写的内容

| 对象 | 范围 | 行为 |
| :--- | :--- | :--- |
| 公式引用 | 全部工作表 | 指向被编辑表的 A1 引用会平移；指向整块被删区域的引用变成 `#REF!` |
| 合并单元格区域 | 被编辑表 | 平移；跨越插入点时扩张；整块被删时移除，报告里记为 `to: null` |
| 自动筛选范围 | 被编辑表 | 与普通区域同样平移或扩张 |
| 冻结窗格 | 被编辑表 | 锚点单元格平移，但不会越过分隔自身的行或列下限 |
| 数据验证 | 被编辑表 | `sqref` 里每个区域平移；被删区域移除 |
| 条件格式 | 被编辑表 | 应用范围（sqref）平移 |
| 原生表格 | 被编辑表 | 表格的 `ref` 平移或扩张 |
| 定义名称 | 工作簿级 | `attr_text` 中指向被编辑表的引用改写 |
| 行高列宽 | 被编辑表 | 尺寸键重新编号 |

## 支持的引用写法

- 相对与绝对坐标的任意组合：`B2`、`$B2`、`B$2`、`$B$2`，`$` 标记在平移后保留
- 区域：`B2:D9`，端点部分绝对也支持
- 跨表引用：`Data!B2`、`'My Sheet'!$A$1:$C$9`（表名内可含双写引号 `''`）。只有表名与被编辑表相同的引用会被处理；不带表名的引用按公式所在表解释
- 公式里的字符串字面量（如 `"See B2"`）永不改写
- 与单元格写法相似但实为函数名的（如 `LOG10(...)`）不会误改，因为引用后面不会紧跟 `(`
- 整行整列引用（`B:B`、`2:2`）原样保留——按 Excel 语义，在范围内插入时它们本就有效

## 平移规则

**在第 i 位插入 N 行或列**：坐标大于等于 i 的全部加 N；区域的两个端点各自平移，因此跨越 i 的区域会扩大 N。

**在第 i 位删除 N 行或列**：i 之前的坐标不变；越过被删块的坐标减 N；块内的单个单元格变成 `#REF!`；部分覆盖块的区域被夹到剩余边界（Excel 同样处理）；整块落在范围内且被完整删除的，公式里变成 `#REF!`，合并与验证里直接移除。

## 移不动的部分（边界）

- **图表锚点与绘图范围**：openpyxl 的图表对象无法可靠往返，锚点原地不动。数据移动后要重建图表
- **图片与图形**：同上
- **条件格式规则里的公式**：应用范围会平移，但 `cell_is`、`expression` 规则内部的公式（如 `$B1>100`）保持原样。它们若引用了被移动的单元格，需要人工核对
- **工作表级定义名称**，以及使用 R1C1 或并集、交集运算符的名称：只有能解析成普通 A1 引用时才改写，其余原样保留
- **公式里的结构化表格引用**（如 `Table1[Sales]`）：它们跟着表格走，无需平移，保持原样

每次运行都会打印一份 JSON 报告，逐项列出改了哪些公式、合并、表格、名称与区域，并附一份固定的 `not_shifted` 清单说明上面这些边界。任何结构调整之后都要看这份报告。

## 一次只做一步

命令行只接受 `--insert-rows`、`--delete-rows`、`--insert-cols`、`--delete-cols` 其中之一，写法为 `IDX[:N]`，列可用字母。

需要连续多步时反复调用——把多个平移合并成一次处理，正是表格工具历来最容易把引用改坏的地方。
